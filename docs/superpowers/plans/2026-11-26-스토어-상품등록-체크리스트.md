# 스토어 상품 등록 체크리스트 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** ② 사전 점검에 "이 상품을 스마트스토어에 올리셨어요?" 질문을 넣고, 아직이면 체크리스트·링크·검색어 한 줄을 보여 준 뒤 그 자리에서 주소(스토어 상품 또는 인스타 프로필)를 받는다.

**Architecture:** 질문은 `server/specs/meta_fields.yaml`에 쓰고 `/fields`가 그대로 내보낸다. 패널 `QuestionStep`이 기존 `help`·`then_ask`를 넓혀 그린다: `help[o].steps`(체크리스트), `then_ask.field`를 답별로, `prefill` 후보 여러 개, `default_if`·`note_if`(앞 답에 따라 권장·안내 바꾸기). 체크 상태는 `FlowState.checks`에 저장.

**Tech Stack:** FastAPI·PyYAML·pytest / React·WXT·vitest·Testing Library

**Spec:** `docs/superpowers/specs/2026-11-26-스토어-상품등록-체크리스트-design.md`

## Global Constraints
- 색·글자 크기는 토큰 클래스만 (hex·rgba·`text-[NNpx]` 금지). `validate-tokens.cjs --dir extension/entrypoints/sidepanel` 통과.
- 문구는 쉬운 해요체. 링크는 새 탭(`target="_blank" rel="noopener noreferrer"`) + `(새 탭)` sr-only.
- 할 일은 체크박스, 다 체크하지 않아도 [다 했어요] 가능. [나중에 할게요]는 같은 무게(밑줄 글자 버튼, 기존 모양).
- 새 칸 `meta.pre.store_product`·`meta.pre.store_url`·`meta.pre.insta_url`은 광고 관리자 칸이 아니다 → `SETTING_ORDER`에 넣지 않는다.

## Review Focus
- 나중에 → 인스타 주소를 받은 뒤 '클릭 주소'에서 스토어를 고르면 주소 칸이 **비어** 있어야 한다 (인스타 주소가 상품 주소로 새지 않게). → Task 2 테스트.
- 검색어가 없는 상태(`state.keywords` 빈 배열)면 검색어 줄을 숨긴다. → Task 2 테스트.
- 패널을 닫았다 열어도 체크가 남는다 (`checks`가 저장 상태에 있음, 예전 저장본에는 `{}`로 채워짐). → Task 2 reducer 테스트.
- 인스타 계정을 비워 둔 채 나중에 → 인스타 주소 칸이 빈 칸으로 나오고 주소 형식 검사가 막는다 (기존 `fill` 동작). → 기존 동작, 별도 테스트 없음.
- 이전 질문으로 돌아가 다른 답을 고를 때, 예전 답과 다른 선택지면 예전 주소를 채우지 않는다. → Task 2 테스트(첫 항목과 같은 테스트).

### Task 2: 패널

**Files:** Modify `extension/lib/api.ts` (타입), `extension/lib/flow.ts` (`checks`, `toggleCheck`), `extension/lib/settings.ts` (`askedFields`가 답별 field 처리), `extension/entrypoints/sidepanel/steps/QuestionStep.tsx`, `extension/tests/questions.test.tsx`, `extension/tests/fixtures-fields.ts`

**Interfaces:**
- `OptionHelp.steps?: { text: string; link?: string; url?: string; hint?: "keywords" }[]`; `steps`가 있으면 `link`·`url`은 없어도 된다.
- `then_ask.field: string | Record<string, string>`; `prefill?: Record<string, string | string[]>`
- `Field.default_if?: Record<string, Record<string, string>> | null`, `Field.note_if?` 같은 모양(값이 안내 문구)
- `FlowState.checks: Record<string, number[]>`; 이벤트 `{ type: "toggleCheck"; key: string; index: number }`
- `QuestionStep`은 `state.keywords`·`state.checks`를 `Question`에 넘긴다.

- [ ] 테스트(실패 먼저):
  - reducer: `toggleCheck` 두 번이면 빠짐; `initialState().checks` 는 `{}`.
  - '아직이에요' → 체크박스 3개, `0 / 3`, 검색어 줄에 `state.keywords` 앞 3개; 체크 클릭 → `toggleCheck` dispatch.
  - 검색어 없으면 검색어 줄 없음.
  - [다 했어요] → 상품 주소 칸 → 넣고 [다음] → `answer(store_product, 올렸어요)` + `meta.pre.store_url`.
  - [나중에 할게요] → 인스타 주소 칸이 ig 계정으로 채워짐 → `아직이에요` + `meta.pre.insta_url`.
  - 전환 위치: answers에 `store_product: 아직이에요` 면 '인스타그램 프로필'에 '권장', 안내 한 줄; 스토어를 고르면 주소 칸 비어 있음. `store_url`이 있으면 스토어 주소 칸이 그 값으로 채워짐.
- [ ] 구현 후 `npx vitest run && npx tsc --noEmit`, 토큰 검사 통과.
