# 분석 페이지 구현 계획 (2026-11-23)

근거: 11/22 회의 정리("4단계 루프 + 다정 방법론 통합, 분석 페이지 화면 흐름"). 이 문서는 제명 담당 4장(화면)·5장(데이터 연결)을 코드로 옮기는 순서다.

## 바뀌는 구조

| | 지금 | 바뀐 뒤 |
|---|---|---|
| 확장 프로그램 | ① 찾기 · ② 세팅 · ③ 결과 파일 올리기·결과 | ① · ② · ③은 **분석 페이지 열기 + 요약 코드 넣기 → 바꿀 칸 안내** |
| 분석 페이지 | 없음 (확장의 보고서 탭) | **웹 페이지** `http://localhost:8000/analysis` (FastAPI가 정적 페이지로 서빙). CSV 업로드 → 7블록 |
| 서버 | `/analyze` 진단 규칙 + 판단 보류 | `/analysis` 새 엔드포인트: 0 검증 → 1 실측 → 2 보정 → 3 시뮬레이션 → 4 판정 → 5 다음 세팅 |

## 6장 논의 사항: 기본값으로 정하고 진행 (회의에서 바꾸면 그대로 따름)

| # | 기본값 | 이유 |
|---|---|---|
| 1 | 3장 채택 제안대로 (필수 5 + 권장 2) | 문서 제안 |
| 2 | 판정 배지 = **1,000원당 도착** (상세에 CPC·CPM·CTR) | 다정 79%가 이 지표로 재현됨 (감마-포아송, 20만 회, 78.8%). 링크 클릭률 기준은 61% |
| 3 | 90/70% 그대로 | 오븐로그 79% → "유력" |
| 4 | 화면 0·1·2·5·6 먼저, 3·4·7 다음 | 시연 동선 우선 |
| 5 | 기본 예시 = 오븐로그 실측 (희수 실측은 파일 받으면 추가) | 지금 가진 데이터 |
| 6 | 챗봇으로 넘기기 = **4자리 코드** (서버가 결과를 코드로 보관 → 확장에 코드 입력) | 같은 서버라 파일 저장·업로드가 필요 없음. JSON 내려받기는 보조로 |
| 7 | 기본 화면 사장님용 + 숫자마다 "이 숫자는 어떻게 나왔나요?" 접기 | 문서 제안 |

## 계산 (서버, numpy만)

| 단계 | 함수 | 내용 |
|---|---|---|
| 0 검증 | `checks(bundle)` | 일자별 합 = 노출 위치 합 대조(지출·노출·클릭), 지출·노출 0인 날, 예산 소진율 50% 미만(예산 열이 있을 때), 빠진 열(랜딩 조회 등) |
| 1 실측 | `summary(bundle)` | 세트별 지출·노출·클릭·도착, CPM·CTR·CPC·랜딩당 비용·클릭→도착, 노출 위치별 지출 |
| 2 보정 | `posteriors(...)` | 비율 = 베타(1+k, 1+n−k), 원당 횟수 = 감마(1+k, 지출). 노출 위치 CTR은 경험적 베이즈 축소(전체 평균으로), 노출 < 기준이면 "참고만" |
| 3 시뮬레이션 | `simulate(budget, days, arm)` | 20만 회: 노출 = 예산 ÷ CPM × 1,000 → 클릭 = 노출 × CTR → 도착 = 클릭 × 도착률. 중앙값·80% 구간·히스토그램 |
| 4 판정 | `verdict(a, b)` | 지표별 P(B>A). 배지 지표는 1,000원당 도착: ≥90% 채택 · 70~90% 유력 · <70% 보류. 일자별 재현(날짜마다 누적 재계산). 95% 구간 겹침 여부 |
| 4 판정 | `min_budget(...)` | 기대 효과(+20%)에서 "90% 확신으로 승자 고를 확률 ≥ 80%"가 되는 그룹당 최소 예산 (시뮬레이션 탐색) |
| 5 다음 세팅 | `next_step(...)` | 판정별 행동 + 기존 진단 규칙(`rules.yaml`)에서 바꿀 칸 **1개** + 3줄 요약 |

## 화면 (웹 페이지, React + Recharts, 확장과 같은 색)

0 시작(올리기 · 예시로 보기 · 5,000원 테스트 준비) → 1 데이터 확인 → 2 한눈에 결과 → 3 어디서 빠졌나 → 4 A vs B → 5 예산 시뮬레이터 → 6 다음 세팅(코드 보여 주기·JSON) → 7 근거 탭.
모든 숫자 = 범위 + 근거 등급(A 실측 / B 매체 추산 / D 가정). 접기 이름 "이 숫자는 어떻게 나왔나요?", 첫 줄 "쉽게 말하면".

## 순서 (TDD, 블록마다 커밋)

1. 서버 계산 0·1·2·4(판정·일자별 재현)·5 + `/analysis` + 결과 코드 보관 `/plan/{code}`
2. 웹 페이지 뼈대 + 화면 0·1·2·6
3. 화면 5 시뮬레이터 (`/simulate` — 슬라이더마다 호출)
4. 확장 ③을 "분석 페이지 열기 + 코드 넣기"로 바꾸기 → 기존 수정 안내로 연결
5. 화면 3·4·7, 최소 검증 예산
6. 오븐로그 실측으로 처음부터 끝까지 리허설 (확인용 브라우저)

## 확인이 필요한 것

- 희수 8장의 최소 검증 예산 정의 그대로인지 (기대 효과 +20%, 90% 확신, 80% 확률)
- 희수 실측 CSV (기본 예시 후보, 두 실험 비교 탭)
- 예산 소진율: 메타 내보내기에 "광고 세트 예산" 열이 있어야 계산 가능
