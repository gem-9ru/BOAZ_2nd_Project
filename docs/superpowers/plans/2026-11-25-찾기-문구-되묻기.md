# ① 찾기 · ② 문구 되묻는 대화형 Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** 사장님이 상품 이름 한 번만 적으면 된다. 나머지는 네이버 자료(키워드 도구·쇼핑인사이트·검색어 트렌드)를 보며 고른다: 분야 → 부르는 말 → 손님 무리 → 좋은 점. 고른 것으로 근거가 붙은 문구 3개를 받는다. 분야는 12개 모두 된다.

**Architecture:**
- 서버
  - 낱말 목록은 `server/specs/rules.yaml`의 `find:`에 모은다.
  - `market.py`는 분야를 받아 뜻을 나눈다. 뜻 묶음마다 손님 무리를 만들고, 검색어 트렌드 한 번 호출로 무리끼리 달별 비교를 한다.
  - `/research`는 무리·꾸밈말·분야를 더해 돌려준다. 하위 호환을 유지한다.
  - `/copies`는 고른 무리와 꾸밈말로 쓰고, 문구마다 근거 낱말을 붙인다.
- 확장: `FindStep`·`CopyStep`을 되묻는 흐름으로 바꾼다.

**Tech Stack:** FastAPI·pandas·pytest(서버), WXT·React 19·Tailwind v4·Vitest(확장)

**Spec:** `docs/superpowers/specs/2026-11-25-찾기-문구-되묻기-design.md` (특히 5장 화면, 6장 서버, 8-1 검토 결정, 10장 분야 확장)

## Global Constraints

- 화면은 `UX_설계원칙.md`와 그 점검표를 따른다. 사장님의 글자 입력은 상품 이름 한 번과 (선택) 좋은 점 직접 적기뿐이고, 나머지는 누르기다.
- 화면 코드에는 hex·rgba·`text-[NNpx]`·`text-white`·`disabled:opacity-N`를 쓰지 않는다. 다음 토큰만 쓴다.
  - 글자: `text-mark/small/caption/label/body/lead/title/number`
  - 색: `on-accent`
  - 꺼진 상태: `disabled:opacity-(--state-disabled-opacity)`
  - 모서리: `rounded-button/card/badge/mark`
- **네이버 숫자는 Claude에 넣지 않는다.** Claude에는 낱말(검색어·꾸밈말), 무리 이름, 달 이름만 넘긴다.
- `/research` 한 번에 데이터랩 HUB 호출은 무리 계산 15번 이하, 분야 찾기 12번(상품마다 한 번)이다. 저장본에서 꺼낸 것은 세지 않는다.
- `COACH_OFFLINE=1`에서 '수제 쿠키'(seeds = `["답례품쿠키","디저트선물","수제쿠키","쿠키선물세트","휘낭시에"]`)는 무리·트렌드·꾸밈말까지 저장본으로 나와야 한다.
- 키는 확장 프로그램과 로그에 넣지 않는다. 오류 문구에 키 값이 섞이면 안 된다(지금 `NaverError` 문구 방식을 따른다).
- 쇼핑인사이트·검색어 트렌드는 상대값이다. 화면에서는 "비중·배수·가장 많은 달"로만 말한다.
- 무리 이름(고정 문구)
  - 선물·답례 → "선물로 찾는 손님"
  - 시즌 → "시즌에 찾는 손님"
  - 상품 → "상품 자체로 찾는 손님"
- 큰 분야 12개 (code → name)
  - 50000000 패션의류 · 50000001 패션잡화 · 50000002 화장품/미용 · 50000003 디지털/가전
  - 50000004 가구/인테리어 · 50000005 출산/육아 · 50000006 식품 · 50000007 스포츠/레저
  - 50000008 생활/건강 · 50000009 여가/생활편의 · 50000010 면세점 · 50005542 도서
- 커밋은 이 계획의 커밋 단계에서만 한다. 푸시는 하지 않는다. `발표자료/`는 커밋하지 않는다.
- 서버 테스트: `.venv/bin/python -m pytest server/tests -q`. 확장 테스트: `cd extension && npx vitest run`. 타입 검사: `cd extension && npx tsc --noEmit`.

## Review Focus

1. **분야를 추정하지 못하는 상품**(예: "zz상품"): 서버는 `category: null`, `segments: []`를 주고 오류를 내지 않는다. 화면은 "분야를 골라 주시면 손님을 찾아볼게요"와 분야 고르기를 보여 준다 → Task 5, Task 8 테스트.
2. **업데이트 전에 저장된 패널 상태**(`research`에 `segments`·`modifiers`가 없음): ① 찾기·② 문구가 깨지지 않고, 지금처럼 보이거나 직접 적기만 보여 준다 → Task 8, Task 9 테스트.
3. **고른 무리의 `audience`가 null**: [이 손님들로 할게요]를 누르기 전에 연령·성별을 직접 고르게 한다. 고르기 전에는 버튼이 꺼져 있다 → Task 8 테스트.
4. **검색어 트렌드 실패**: 무리 카드의 달별 막대를 쇼핑인사이트 `monthly`로 대신하고, `trend_source: "shopping"`으로 출처를 바꿔 적는다 → Task 3 테스트.
5. **빵·과자가 아닌 분야**(예: "립밤", "캠핑 의자"): 입력한 낱말이 든 연관 검색어로 상품 무리가 생기고, 빵 낱말(휘낭시에 등)은 상품으로 잡히지 않는다 → Task 1 테스트.

### Task 3: 손님 무리(segments)

**Files:**
- Modify: `server/engine/market.py`
- Test: `server/tests/test_segments.py` (새 파일, 같은 `isolated` 픽스처)

**Interfaces:**
- Consumes: Task 1의 `classify/recommend`(seeds = `product_words`), Task 2의 `api.search_trend`, 지금의 `audience(keyword, category, online)`
- Produces:
  - `market.SEGMENT_LABEL: Dict[str, str]`: Global Constraints의 무리 이름 3개
  - `market.trend_by_group(groups: Dict[str, List[str]], online=True) -> Dict[str, dict]`
    - 값은 `{"monthly": {"YYYY-MM": 0~100}, "peak_month": int|None, "seasonal": bool}`이다.
    - monthly는 무리마다 그 무리의 최고값을 100으로 맞춘다.
    - `seasonal`은 최고 달이 평균의 `SEASON_PEAK`배 이상인지다.
    - 응답이 없으면 `{}`다.
  - `market.segment_line(aud: Optional[dict]) -> str`
    - 지금 `headline`에서 "{키워드}을 찾는 사람은 " 앞부분을 뺀 문장이다. 예: "30대 여성이 분야 평균의 2.8배, 12월에 가장 많이 찾아요".
    - aud가 None이면 "누가 찾는지 자료가 아직 없어요"다.
    - `headline`은 이 함수를 써서 같은 문장을 만든다(지금 테스트의 headline 문장은 그대로).
  - `market.segments(kw, rec, category: Optional[str], online=True, keep: Optional[List[str]] = None) -> List[dict]`
    1. `rec` 중 `keep`에 든 것만 남긴다(keep이 None이면 전부). 남은 말을 intent(선물·답례/시즌/상품)로 묶는다. 검색수 합이 큰 묶음부터 최대 3개다.
    2. 묶음마다 `lead`는 검색수 1위다. `audience(lead, category, online)`를 부른다. category가 None이면 audience는 None이다(호출 안 함).
    3. `trend_by_group({intent: keywords[:5]})`를 **한 번** 부른다. 그 무리 트렌드가 없으면 `audience.monthly`로 대신하고 `trend_source="shopping"`, 둘 다 없으면 None이다.
    4. 무리의 `audience.monthly`·`peak_month`를 트렌드 값으로 덮어쓴 뒤 `line = segment_line(aud)`를 만든다.
    5. 돌려주는 dict 키: `intent, label, keywords, total_qc(int), lead, audience({female, ages, top_age, index}|None), trend, trend_source("search"|"shopping"|None), line`
