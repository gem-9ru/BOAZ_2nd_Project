# 광고 코치 챗봇 퍼널 (2026-11-22, 코드 기준)

이 문서는 **사장님이 사이드 패널에서 거치는 단계**를 코드(`extension/lib/flow.ts`)와 1:1로 맞춰 적은 것입니다.
광고 성과 깔때기(노출 → 클릭 → 도착)는 ③ 분석의 내용이고, 여기서 말하는 퍼널은 **사람이 챗봇을 따라가는 길**입니다.

## 읽는 법

단계마다 같은 칸을 채웠습니다.

| 칸 | 뜻 |
|---|---|
| 들어오는 조건 | 이 화면이 보이려면 상태(`FlowState`)가 어때야 하나 |
| 사장님이 하는 일 | 화면에서 누르거나 넣는 것 |
| 시스템이 하는 일 | 서버 호출, 계산, 저장 |
| 나가는 조건 | 어떤 이벤트(`FlowEvent`)로 다음 단계가 되나 |
| 막히는 곳 | 실패·빈 결과·이탈. **[빈틈]** 은 지금 코드에 처리가 없는 곳 |
| 재는 값 | 이 단계를 잘 넘겼는지 볼 숫자 (아직 수집 코드 없음) |

상태는 `chrome.storage.local`의 `coach.v3.state` 하나에 저장되고, 패널을 닫았다 열어도 그 단계에서 이어집니다. 모든 단계에서 "처음부터"(`reset`)를 누르면 F0으로 돌아갑니다. **뒤로 가기는 없습니다.**

## 한눈에

```
① 찾기      F1 상품 입력 → F2 타겟·키워드 확인
② 세팅      F3 문구 고르기 → F4 질문 9개 → F5 광고 관리자 안내(14칸) → [사장님이 직접 게시]
            F6 기다리기 (광고 기간)
③ 분석      F7 결과 내보내기 안내(선택) → F8 결과 파일 올리기 → F9 결과 보기
            ├ 바꿀 칸 있음 → F10 바꾸러 가기(수정 안내) → F6 으로 (다음 회차)
            └ 바꿀 칸 없음 → "이대로 계속" → F6 으로
```

| 단계 | `step` | `guide` | 화면 |
|---|---|---|---|
| F1·F2 | `find` | null | FindStep |
| F3 | `copy` | null | CopyStep |
| F4 | `questions` | null | QuestionStep |
| F5 | `guide` | `{mode:"create"}` | GuideStep + 광고 관리자 위 캐릭터 |
| F6 | `wait` | null | WaitStep |
| F7 | `wait` | `{mode:"export"}` | GuideStep + 캐릭터 |
| F8 | `upload` | null | UploadStep |
| F9 | `result` | null | ResultStep (+ 보고서 탭) |
| F10 | `fix` | `{mode:"edit"}` | GuideStep + 캐릭터 |

## ① 찾기

### F1 상품 입력
- **들어오는 조건**: 처음 열었을 때, 또는 "처음부터" 뒤 (`step: find`, `research` 없음)
- **사장님이 하는 일**: 파는 상품을 한 단어로 넣고 "찾아보기" 또는 Enter
- **시스템이 하는 일**: `POST /research {product}` → 네이버 검색광고 키워드 도구(연관 키워드·월 검색수) + 데이터랩(연령·성별 비중). 네이버 호출은 한 번에 하나씩(`_NAVER_LOCK`). 실패하면 저장본(cache)으로 대신하고 `source: "cache"`와 조회일을 같이 돌려줌
- **나가는 조건**: 응답이 오면 `researched` → 같은 화면에 F2가 펼쳐짐 (단계는 그대로 `find`)
- **막히는 곳**
  - 서버가 꺼짐 → "도우미 서버에 연결할 수 없어요" + 다시 시도 (입력값 유지)
  - 서버 5xx → "서버에서 문제가 생겼어요"
  - 응답에 `notice`가 있으면(추천 키워드가 비었거나 네이버 오류) 안내 문장 + "직접 정하고 계속할게요" → 연령대(20~60대, 기본 30대)·성별(모두/여성/남성, 기본 모두)을 골라 `confirmTarget`. 키워드는 상품 이름 하나로 대신함 (2026-11-22 고침)
- **재는 값**: 입력 수 / 결과가 나온 수 / `notice`로 끝난 수 / 저장본으로 대신한 비율

### F2 타겟·키워드 확인
- **들어오는 조건**: `research`가 있고 `notice`가 없음
- **보이는 것**: "가장 눈에 띄게 찾는 사람"(예: 30대 여성), 연령대 막대, 키워드 최대 10개(월 검색수), 출처·조회일
- **사장님이 하는 일**: 빼고 싶은 키워드 누르기(`toggleKeyword`, 다시 누르면 되살림) → "이 사람들로 할게요"
- **시스템이 하는 일**: 성별은 여성 비중 0.6 이상이면 여성, 0.4 이하면 남성, 그 사이는 전체. 나이는 가장 많은 연령대 10년 폭(18~65로 자름)
- **나가는 조건**: `confirmTarget {target, keywords}` → F3
- **막히는 곳**
  - 키워드를 전부 빼면 "이 사람들로 할게요"가 꺼짐 (넘어가지 않음)
  - 출처 줄은 부분별 날짜를 따로 보여 줌: "검색어·연령 오늘 조회 · 분야 평균 11월 15일 저장본" (`sources`, 2026-11-22). 시연 상품(수제 쿠키)은 고정 저장본(`server/data/cache_examples/`)을 먼저 쓰므로 둘 다 11월 15일로 나옴
  - 타겟(연령·성별)은 여기서 고칠 수 없음. 그대로 받거나 처음부터 **[빈틈]**
- **재는 값**: 확인까지 간 비율 / 뺀 키워드 수 평균

## ② 세팅

### F3 광고 문구 고르기
- **들어오는 조건**: `step: copy`
- **사장님이 하는 일**: 상품의 좋은 점 한두 마디 → "문구 써 주세요" → 3안 중 하나 "이 문구로 할게요"
- **시스템이 하는 일**: `POST /copies {product, strengths, keywords}` → Claude가 메타 문구 3개(제목 + 기본 문구). Claude를 못 쓰면 문장 틀로 대신하고 `source`에 표시. 최저가·1위 같은 사실 아닌 말은 넣지 않음
- **나가는 조건**: `pickCopy {copy}` → F4
- **막히는 곳**: 서버 오류는 다시 시도. **[빈틈]** 3안이 다 마음에 안 들 때 "다시 써 주세요"가 없음(좋은 점을 고쳐 다시 누르면 되지만 안내 문구 없음). 고른 문구를 직접 고칠 칸도 없음
- **재는 값**: 문구 요청 → 선택까지 걸린 시간 / 몇 안을 고르나 / 문장 틀로 대신한 비율

### F4 질문 9개
- **들어오는 조건**: `step: questions`. 질문 목록은 `GET /fields`로 받아 옴(받는 동안 "질문을 불러오는 중이에요…")
- **질문**(순서대로): 페이스북 페이지 있나 · 인스타그램 계정 · 특별 광고 카테고리 · 전환 위치 · 기간(7/14/30일) · 지역 · 형식 · 웹사이트 URL · 사진 종류. 각 질문에 권장값과 이유가 붙음
- **묻지 않는 칸**: 캠페인 목표(트래픽)와 연령·성별(F2 결과)은 미리 채움. 그 밖의 30칸은 권장값으로 두고 "묻지 않고 이렇게 두었어요"에 접어서 보여 줌
- **시스템이 하는 일**: 마지막 답에서 `buildSettings` → 광고 관리자에 넣을 13개 세팅값과 종료 날짜(오늘 + 기간)
- **나가는 조건**: `questionsDone {settings, endDate}` → F5
- **막히는 곳**: 질문을 못 불러오면 다시 시도. **[빈틈]** 이전 질문으로 돌아갈 수 없음. "페이스북 페이지 없어요"를 골라도 따로 갈림길이 없음(광고 관리자에서 '페이지 만들기'를 짚기만 함). 웹사이트 URL 형식 검사 없음
- **재는 값**: 질문별 이탈 / 권장값을 그대로 고른 비율

### F5 광고 관리자 안내 (캐릭터)
- **들어오는 조건**: `guide: {mode: "create"}`
- **사장님이 하는 일**: "광고 관리자 열기" → 열린 탭에서 캐릭터가 짚는 칸을 차례로 채움. 칸을 바꾸면(`change`) 저절로 다음, 손으로 하는 칸은 말풍선의 "했어요"
- **시스템이 하는 일**
  - 이미 열린 광고 관리자 탭이 있으면 그 탭을 씀. 콘텐츠 스크립트에 `guide:start`(최대 6번 다시 보냄)
  - 안내 목록 `extension/guide/meta_traffic.json` 14칸을 순서대로 찾음. 칸은 화면 글자로만 찾음(`aria-label`, `aria-labelledby`, 라벨 글자, placeholder, 구역 제목, 버튼 글자). 클래스 이름은 쓰지 않음
  - 진짜 칸이 아직 없으면 그 전 단계를 짚는 **힌트**를 씀(예: 목표 칸이 없으면 "+ 만들기"를 먼저 누르라고). 1초마다 다시 보고 진짜 칸이 나타나면 옮겨 감
  - 진행은 백그라운드가 저장 → 패널을 닫아도 이어짐
  - 화면 언어가 한국어가 아니면 먼저 바꾸라고 함. 세 번(2초 간격) 못 찾으면 대체 그림과 설명
  - **게시 버튼은 절대 누르지 않음.** 마지막 칸은 "동의하고 게시"를 짚기만 함
- **나가는 조건**: 마지막 칸을 마치면 `guideDone` → F6
- **실제 화면 순서** (2026-11-22 팀 계정에서 확인):
  `+ 만들기` → 목표 창 '트래픽' → '계속' → 설정 창 '수동 트래픽 캠페인' → '계속' → 캠페인(특별 광고 카테고리) → '다음' → 광고 세트(전환 위치 '웹사이트', 종료 날짜, 위치, 타겟 추천 › 설정 표시 › 연령·성별) → '다음' → 광고(대표 계정, 형식, 광고 만들기(사진), 문구·제목, 웹사이트 URL) → '동의하고 게시'(사장님이 직접)
- **막히는 곳**
  - 문구·제목 칸은 **사진을 넣은 뒤에야 생김**. 사진이 없으면 '크리에이티브 설정'만 짚을 수 있음 (확인 필요)
  - 팀 계정은 페이스북 페이지가 없어 '페이지 만들기'만 보임
  - **[빈틈]** 사장님이 게시를 눌렀는지 알 길이 없음. 마지막 칸 "했어요"를 게시로 간주
- **재는 값**: 칸별 찾음/못 찾음(대체 그림) 비율 · 칸별 머문 시간 · 게시까지 간 비율

### F6 기다리기
- **들어오는 조건**: `step: wait`, `guide` 없음
- **보이는 것**: "{종료 날짜 다음날}에 결과를 보러 오세요" + "결과 내보내는 법 보기" + "결과 파일 올리기"
- **나가는 조건**: 내보내는 법 → F7 / 바로 올리기 → F8
- **막히는 곳**: **[빈틈]** 알림이 없음. 사장님이 날짜를 기억해 다시 열어야 함. 기간 중간에 미리 볼 방법도 없음
- **재는 값**: 종료일 이후 돌아온 비율 · 돌아오기까지 걸린 날

## ③ 분석

### F7 결과 내보내기 안내 (선택)
- **들어오는 조건**: `guide: {mode: "export"}`
- **안내**: '보고서' → '분석 기준'에서 일·노출 위치 → '내보내기'(CSV)
- **나가는 조건**: 마치면 `startUpload` → F8
- **막히는 곳**: **[빈틈]** 이 세 칸은 아직 실제 화면에서 확인하지 않음 (짐작한 버튼 글자)

### F8 결과 파일 올리기
- **사장님이 하는 일**: CSV 고르기 → "결과 파일 올리기"
- **시스템이 하는 일**: `POST /analyze` → 메타 내보내기(일 × 노출 위치) 또는 팀 정리본(세로형)을 읽어 일별·노출 위치별 표로 바꿈. 합계 행은 뺌
- **막히는 곳**: 링크 클릭 열이 없거나 모르는 파일 → 400과 고칠 방법 안내, 파일은 기억해 두고 다시 시도 가능
- **나가는 조건**: `analyzed {result}` → F9

### F9 결과 보기
- **보이는 것**: 카드 3장 — ❶ 무엇이 문제였나 ❷ 이 칸을 이렇게 바꾸세요 ❸ 바꾸면(또는 기간을 늘리면) 이만큼 · 근거 등급(실측/가설). "보고서 크게 보기"는 새 탭(1920×1080 대시보드)
- **판단 규칙**
  - 진단 규칙이 걸리고 비율의 90% 범위가 기준선을 넘지 않으면 → **문제 확정**(`fired`): 바꿀 칸 + 예상 범위(규칙에 적힌 값, 지금은 가설)
  - 링크 클릭 100회 미만이거나 범위가 기준선에 걸치면 → **판단 보류**(`hold`): 종료 날짜 7일 연장 + 데이터가 2배일 때 범위 + A/B면 "B가 나을 확률"
  - 아무 규칙도 안 걸리면 → **정상**(`normal`)
- **나가는 조건**: 바꿀 칸이 있으면 "바꾸러 가기"(`startFix`) → F10, 없으면 "이대로 계속 돌릴게요"(`guideDone`) → F6
- **오븐로그 실측의 결과**: 판단 보류(링크 클릭 30) · 종료 날짜 +7일 · B가 나을 확률 약 61% · 링크 클릭률 1.2~2.2% → 1.3~2.0%

### F10 바꾸러 가기 (수정 안내)
- **들어오는 조건**: `step: fix`, `guide: {mode: "edit"}`. 안내는 결과의 `changes`에 든 칸만
- **수정 칸** (확인함): 노출 위치('설정 더 보기' › '앱 및 사이트' 끄기) · 종료 날짜('종료 날짜 설정') · 기본 문구 · 크리에이티브 테스트('테스트 설정')
- **나가는 조건**: 마치면(또는 안내할 칸이 없어 "바꿨어요") `guideDone` → F6 (다음 회차)
- **막히는 곳**: **[빈틈]** 다음 회차 결과를 올리면 이전 결과를 **덮어씀**. "지난번보다 얼마나 나아졌나"를 비교할 수 없음. 회차 기록이 없음
