# ① 찾기 · ② 문구: 네이버 자료로 되묻는 대화형 — 설계

날짜: 2026-11-25 · 범위: 크롬 확장 사이드 패널 ① 찾기(`FindStep.tsx`), ② 문구(`CopyStep.tsx`)와 이를 받치는 서버(`/research`, `/copies`)

## 1. 왜 하나

지금 두 질문은 얕다.
- **"어떤 상품을 파세요?"**: 상품 이름 한 줄을 받는다. 그 뒤 네이버 자료로 손님 한 무리(예: 30대 여성)를 정하고, 사장님은 검색어를 빼는 것만 할 수 있다.
- **"상품의 좋은 점을 한두 마디로"**: 빈칸 하나다. 광고를 처음 하는 사장님은 무엇을 적어야 할지 모르고, 적은 말이 손님이 쓰는 말과 이어지지도 않는다.

사용자(기획자)의 요청: 네이버 API를 살펴서 이 두 질문을 **훨씬 자세하고 친절하게** 만들고, **검색어 트렌드**도 쓴다.

방향: 사장님이 빈칸을 채우게 하지 않는다. 네이버에서 찾은 **실제 손님의 말과 숫자를 보여 주고 "사장님 상품에 맞는 것을 골라 주세요"라고 되묻는다**. 고른 것은 다음 단계로 근거째 이어진다: 손님 무리 → 좋은 점 → 문구.

## 2. 목표 · 하지 않을 것 · 실패

**목표**
1. ① 찾기에서 사장님이 세 가지를 직접 고른다: 분야, 내 상품을 부르는 말, 손님 무리.
2. 손님 무리 후보는 2~3개다. 무리마다 네이버 근거를 한 줄씩 붙인다.
   - 누가 찾는지: 쇼핑인사이트
   - 언제 많이 찾는지: 검색어 트렌드
   - 얼마나 찾는지: 키워드 도구
3. ② 좋은 점은 손님이 실제로 검색하는 꾸밈말(예: 개별포장·비건·당일발송) 중에서 고르고, 직접 적기도 된다.
4. 문구 3개는 고른 손님 무리와 고른 좋은 점으로 쓴다. 문구마다 어느 검색어에서 나왔는지 보여 준다.

**하지 않을 것**
- 경쟁 상품 가격 비교. 네이버 쇼핑 검색 API가 2026-07-31에 끝나 자료를 얻을 수 없다.
- 메타 광고 관리자 쪽 바꾸기(뭉치 안내). 이번 범위 밖이다. 다만 고른 무리의 연령·성별은 지금처럼 `target`으로 넘긴다.
- 광고 세트를 여러 개 만드는 것. 메타 광고 세트 하나에는 연령 범위와 성별을 하나씩만 넣으므로 무리도 하나만 고른다.

**실패로 보는 것** (돌아가더라도)
- 질문이 늘어 사장님이 ① 찾기에서 지친다. 사장님이 하는 일은 **누르기**여야 하고, 글자 입력은 상품 이름 한 번이어야 한다.
- 근거 없는 숫자나 문장이 나온다. 모든 숫자에는 출처와 조회일을 붙인다. 표본이 적은 배수는 말하지 않는다(지금 `MIN_AGE_SHARE`·`HIGH_INDEX` 기준을 유지).
- 네이버가 안 될 때 막힌다. 저장본 → 직접 정하기로 이어지는, 지금 있는 막다른 길 없음 원칙을 유지한다.

## 3. 지킬 것

- 화면은 `UX_설계원칙.md`와 그 점검표를 따른다.
- 색·글자 크기는 `design-system/tokens.json`의 토큰만 쓴다. 화면 코드에 hex·rgba·`text-[NNpx]`를 쓰지 않는다.
- 네이버 호출 한도
  - 키워드 도구는 요청 간격을 둔다(`KW_GAP`). 429가 오면 5분 쉰다.
  - 데이터랩 HUB는 기능별로 월 5만 건, 초당 50건이다.
  - `/research` 한 번에 HUB 호출은 **15번 이하**로 한다(아래 계산).
- 저장본: 시연 상품 '수제 쿠키'는 오프라인(`COACH_OFFLINE=1`)에서도 전 과정이 돌아야 한다. 새로 부르는 검색어 트렌드도 `server/data/cache_examples/`에 저장본을 둔다.
- 키는 확장 프로그램과 로그에 넣지 않는다.
- ⚠ **약관 확인**: 네이버 약관 개정으로 "AI 입력 금지" 조항이 생겼다는 보도가 있다. 데이터랩 자료에도 적용되는지 확인되지 않았다.
  - 이 설계는 네이버 **숫자**를 Claude에 넣지 않는다. 숫자는 화면 근거로만 쓴다.
  - Claude에는 사장님이 고른 **낱말**(검색어·꾸밈말)과 무리 이름만 넘긴다. 지금 `/copies`도 검색어를 넘기고 있다.
  - 약관에서 이것도 금지로 확인되면 문장 틀(template)로만 쓰는 스위치(`COACH_NO_LLM=1`, 이미 있음)로 돌린다.

## 4. 만드는 방법 (검토한 세 가지)

| 방법 | 내용 | 장단 |
|---|---|---|
| A. 질문 마법사 | 한 화면에 한 질문: 이름 → 분야 → 판매처 → 좋은 점 → 결과 | 친절하지만 화면이 많다. 자료를 보기 전에 답해야 한다 |
| B. 지금 화면 넓히기 | 이름만 받고 결과 카드만 늘린다 | 빠르지만 사장님은 여전히 보기만 한다 |
| **C. 되묻는 대화형 (선택)** | 짧게 묻고, 찾은 자료를 보여 주며 하나씩 되묻는다 | 사장님이 직접 고르고 근거가 이어진다. 서버 일이 가장 많다 |

사용자가 **C**를 골랐다(2026-11-25).

## 5. 화면 흐름

한 화면 안에서 위에서 아래로 쌓이는 대화다. 앞 질문에 답해야 다음 묶음이 열린다. 앞 답을 바꾸면 그 아래는 다시 계산한다(지금의 `stale` 처리처럼 흐리게 둔 뒤 갱신).

### ① 찾기

```
뭉치: 어떤 상품을 파세요? 네이버에서 손님이 어떤 말로, 언제, 누가 찾는지 알아볼게요.
[ 수제 쿠키            ] [찾아보기]

1) 분야  ─ "쿠키는 '식품'으로 볼게요. 맞나요?"  (식품 ✓) [바꾸기 ▾ 12개 큰 분야]
2) 내 상품을 부르는 말
   "손님은 이렇게도 불러요. 사장님 상품에 맞지 않는 말은 눌러서 빼 주세요."
   [수제쿠키 월 9.3천 ✓] [답례품쿠키 월 2.1천 ✓] [쿠키선물세트 ✓] …
   ▸ 광고에서 뺄 말 N개 (만들기·매장·관련 낮음) — 지금처럼 접힘
3) 손님 무리 고르기
   "이 말들을 찾는 손님을 세 무리로 나눠 봤어요. 광고를 보여 줄 무리를 하나 골라 주세요."
   ┌ 선물로 찾는 손님 ───────────────┐
   │ 30대 여성이 분야 평균의 2.8배          │
   │ 12월에 가장 많이 (작은 달별 막대 12개)│
   │ 대표 검색어: 답례품쿠키 · 월 2.1천    │
   └────────────────────────── (고르기) ┘
   ┌ 시즌에 찾는 손님 … ┐ ┌ 상품 자체로 찾는 손님 … ┐
   출처: 네이버 검색광고·데이터랩 — 오늘 조회 / 11월 15일 저장본
[이 손님들로 할게요]
```

- **분야**
  - 쇼핑인사이트 큰 분야 12개 중 하나다(아래 표).
  - 서버가 상품 이름의 낱말로 추정해 미리 고른다. 추정하지 못하면 고르라고 묻는다.
  - 분야를 바꾸면 손님 무리만 다시 계산한다. 키워드 도구는 분야와 상관없다.
- **부르는 말**: 지금의 검색어 켜고 끄기와 같다. 고른 말이 손님 무리 계산과 ② 문구에 쓰인다.
- **손님 무리**
  - 뜻 묶음(`intent`: 선물·답례 / 시즌 / 상품)마다 하나씩 만든다. 고른 말이 있는 묶음만 보여 준다.
  - 최대 3개이고, 검색수 합이 큰 순서로 놓는다.
  - 자료가 없는 묶음은 카드에 "누가 찾는지 자료가 아직 없어요"라고 쓰고, 고를 수는 있게 한다(연령·성별은 직접 정하기로).
- **고른 무리 → `target`**: 대표 연령대 → `ageGroupToRange`, 여성 비중 → `genderFrom`. 지금 함수를 그대로 쓴다.

### ② 문구 (좋은 점 → 문구)

```
뭉치: 손님이 '수제 쿠키'를 찾을 때 함께 쓰는 말이에요.
      사장님 상품에 해당하는 것을 눌러 주세요. 문구에 그대로 넣을게요.
   포장   [개별포장 월 1.2천] [선물포장] [박스]
   맛·재료 [버터] [초코] [무설탕] [비건]
   배송   [당일발송] [택배]
   양     [대용량] [소량]
   그 밖  [수제] [국산] …
   + 직접 적기 [                ]  (예: 버터 듬뿍)
   고른 손님: 선물로 찾는 30대 여성 · 12월에 많음  (① 찾기에서 고름, 바꾸기)
[문구 써 주세요]
 1안  제목 / 본문
      근거: 답례품쿠키 · 개별포장 · 선물로 찾는 손님
      [이 문구로 할게요]
```

- 꾸밈말 후보는 손님 무리와 상관없이 같은 연관 검색어 목록에서 뽑는다. 최대 15개다.
- 아무것도 고르지 않고 직접 적기도 비우면 버튼을 잠근다. 안내: "▲ 하나 이상 고르거나 적어 주세요".
- 문구 바로 아래 "근거" 줄에 문구를 만들 때 넣은 낱말을 보여 준다. 지금 있는 "사실이 아닌 말은 넣지 않아요" 안내는 유지한다.

## 6. 서버

### 6-1. `/research` 바뀐 입력·출력

입력: `{product, seeds?, category?}`. `category`를 비우면 서버가 추정한다.

출력: 지금 필드는 유지하고 아래를 더한다(확장의 지금 화면이 깨지지 않게).

```jsonc
{
  "category": {"code": "50000006", "name": "식품", "guessed": true},
  "categories": [{"code": "50000000", "name": "패션의류"}, ...],   // 12개
  "segments": [
    {
      "intent": "선물·답례", "label": "선물로 찾는 손님",
      "keywords": ["답례품쿠키", ...],        // 이 묶음의 추천 검색어 (검색수 순)
      "total_qc": 5400,
      "lead": "답례품쿠키",                   // 손님을 조회한 대표 검색어
      "audience": {"female": 0.81, "ages": {...}, "top_age": "30", "index": {...}} | null,
      "trend": {"monthly": {"2025-12": 100, ...}, "peak_month": 12, "seasonal": true} | null,
      "line": "30대 여성이 분야 평균의 2.8배, 12월에 가장 많이 찾아요"   // market.headline과 같은 규칙
    }
  ],
  "modifiers": [
    {"word": "개별포장", "group": "포장", "total_qc": 1200, "examples": ["개별포장쿠키", "쿠키개별포장"]}
  ]
}
```

- `headline`·`audience`(지금 필드)는 첫 번째 무리의 값으로 채워 하위 호환을 지킨다.

### 6-2. 계산

- **분야 추정** `market.guess_category(product, online) -> code | None`: 낱말 목록이 아니라 실제 검색 결과로 정한다(10장).
- **무리** `market.segments(kw, rec, category)`
  - 추천 검색어를 `intent`로 묶는다.
  - 묶음마다 대표 검색어 1개를 정하고, 쇼핑인사이트로 성별·연령·기기를 받는다(`audience()`를 그대로 쓰고 분야만 인자로).
  - 분야 평균(baseline)은 분야당 2번 부른다.
- **검색어 트렌드** `naver_api.search_trend(groups, ...)`
  - 경로는 `/search-trend/v1/search`(예전 `src/engine/naver_hub.py`에서 확인)다.
  - 무리마다 상위 검색어 5개를 `keywordGroups` 하나로 넣고, **한 번 호출로 모든 무리를 비교**한다. 기간은 지난 12개월, 월 단위.
  - `peak_month`와 `seasonal`은 지금 `SEASON_PEAK`(1.2배) 규칙과 같다.
  - 저장·오류 처리는 `fetch_cached`와 `_guarded`를 쓴다.
- **HUB 호출 수**: 무리 3개 × (성별·연령·기기 3번) + 분야 평균 2번 + 트렌드 1번 = **12번**.
- **꾸밈말** `market.modifiers(kw, seeds) -> list`
  - 제외(만들기·매장) 묶음을 뺀 연관 검색어에서, 상품 낱말·사장님이 적은 말을 지운 나머지 2~6글자를 모은다.
  - 같은 꾸밈말끼리 검색수를 더하고, 상위 15개를 남긴다.
  - 묶음(포장·맛·재료·배송·양·그 밖)은 `rules.yaml` 낱말 목록으로 정한다. 목록에 없으면 '그 밖'이다.
  - 선물·시즌 낱말과 지역·매장 낱말은 꾸밈말에서 뺀다. 이것들은 무리로 이미 쓰인다.

### 6-3. `/copies`

- 입력에 `segment: {intent, label, top_age, gender, peak_month}`과 `strengths`(고른 꾸밈말 + 직접 적은 말)를 받는다.
- Claude 프롬프트에 무리 이름과 시기 낱말(예: "12월 선물")을 넣는다. 숫자는 넣지 않는다.
- 출력 각 문구에 `basis: [낱말...]`를 붙인다. 넣은 낱말 중 문구 글자에 실제로 들어간 것만 담는다.
- 문장 틀(template)에도 무리별 틀을 하나씩 더한다(선물: "~ 답례로", 시즌: "{달}월 ~" 등).

## 7. 확장 (사이드 패널)

- `lib/api.ts`: `Research`에 `category`·`categories`·`segments`·`modifiers`를 더한다. `research(product, category?)`로 바꾼다. `Copy`에 `basis?`를 더한다.
- `lib/flow.ts`
  - `FlowState`에 `category?`, `segment?`(고른 무리), `strengths: string[]`를 더한다.
  - 이벤트 `pickCategory`, `pickSegment`를 더한다. `confirmTarget`은 segment를 함께 받는다.
- `FindStep.tsx`: 5장의 ① 흐름. 길어지면 `find/` 아래로 나눈다(`CategoryPick`, `NamePick`, `SegmentCards`).
- `CopyStep.tsx`: 5장의 ② 흐름.
- 연령 막대(지금 그림)는 고른 무리 카드를 펼친 곳에 둔다. 달별 막대 12개는 작은 막대 그림으로 그리고, 토큰 색을 쓴다.

## 8-1. 검토에서 정한 것 (설계자 판단, 확인해 주세요)

1. **말을 끄고 켤 때**: 서버를 다시 부르지 않고 화면에서 무리의 검색어 목록만 거른다.
   - 사장님이 어떤 무리의 대표 검색어(`lead`)를 끄면, 그 카드에 "[이 말로 손님 다시 찾기]" 버튼을 띄운다.
   - 이 버튼은 `/research`에 `keywords`(켜 둔 말 목록) 입력을 함께 보내 다시 계산한다. 6-1 입력에 `keywords?`를 더한다.
2. **대표 검색어 `lead`**: 무리 안에서 검색수 1위로 정한다. 조회 전에 정해서 무리마다 쇼핑인사이트 1세트(3번)만 부른다. 지금의 배수 기준 `lead_audience`는 무리 안에서는 쓰지 않는다.
3. **달별 막대·가장 많은 달**: 검색어 트렌드 값을 쓴다. 트렌드를 못 받으면 쇼핑인사이트 `monthly`로 대신하고, 카드 출처 줄에 어느 자료인지 적는다.
4. **분야를 추정하지 못했을 때**
   - ① 2) 부르는 말은 그대로 보여 준다(키워드 도구는 분야가 필요 없음). 3) 무리 카드 자리에는 "분야를 골라 주시면 손님을 찾아볼게요"와 분야 고르기만 둔다. 식품으로 먼저 계산하지 않는다.
   - 저장본이 없는 분야(오프라인)라면 카드에 "누가 찾는지 자료가 아직 없어요"를 띄우고 직접 정하기로 간다.
5. **무리가 1개일 때**: 카드를 보여 주고 미리 골라 둔다. **0개일 때**는 지금의 `NoData`(직접 정하기)로 간다.
6. **HUB 15번 한도**: `/research` 한 번 요청 기준이다. 저장본에서 꺼낸 것은 세지 않는다.

## 9. 만드는 사람에게 맡기는 것

- 꾸밈말 추출의 세부 규칙(조사 떼기, 띄어쓰기 변형 합치기)과 묶음 낱말 목록의 초판.
- 화면 컴포넌트를 어떻게 나눌지, 무리 카드의 달별 막대를 그리는 방법.
- 테스트 저장본(검색어 트렌드)을 만드는 방법. 실제 키로 한 번 받아 `cache_examples`에 둔다.

## 10. 알려진 한계

- (2026-11-25 사용자 요청으로 목표로 올림) 베이커리 중심이던 것을 **분야 12개 모두**로 넓힌다. **손으로 만든 분야별 상품 낱말 목록은 두지 않는다.** 사장님이 입력한 낱말을 실제로 검색한 결과로 정한다.
  - **상품 판정**: 연관 검색어에 사장님이 입력한 낱말이 들어 있는지로 본다. 낱말은 상품 이름과 seed, 상품 이름을 띄어쓰기로 나눈 조각(2글자 이상)이다. 지금의 오타·변형 판정(`is_variant`)도 쓴다. `PRODUCT_WORDS`는 지운다.
  - **분야 판정**: 상품 이름(띄어쓰기 없앰)으로 쇼핑인사이트 `/shopping/v1/category/keywords`를 분야 12개에 한 번씩 부른다. 달별 자료가 가장 많이 나온 분야를 고른다(지난 12개월 중 6개 이상일 때만).
    - 2026-11-25 실측: 립밤 → 화장품 12 / 패션의류 2 / 식품 1 / 스포츠 0. 쿠키 → 식품 12 / 패션의류 1 / 화장품 0 / 스포츠 0.
    - 1위와 2위의 자료 수가 같거나, 6개 넘는 분야가 없으면 추정하지 않고 사장님께 묻는다.
    - 이 12번은 상품마다 한 번이고 저장본에 남는다. 무리 계산(12번)과 따로 센다.
  - 분야에 묶이지 않는 공통 낱말(선물·시즌·지역·매장·만들기, 꾸밈말 묶음 이름)만 `server/specs/rules.yaml`의 `find:`에 둔다.
- 쇼핑인사이트·검색어 트렌드는 **상대값**이다(사람 수가 아님). 화면에는 "비중·배수·가장 많은 달"로만 말한다.
