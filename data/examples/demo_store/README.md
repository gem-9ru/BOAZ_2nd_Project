# 시연용 가상 데이터: 스마트스토어 원두 로스터리 (2026-08 ~ 2026-10)

**모두 가짜 데이터입니다.** 실제 가게·주문·사람과 관계없고, 개인정보 항목(이름·연락처·주소)은 처음부터 만들지 않습니다.
다시 만들기: `.venv/bin/python data/examples/demo_store/make_demo.py` (시드 고정이라 늘 같은 파일).

| 파일 | 형식 기준 | 코치에서 쓰는 곳 |
|---|---|---|
| `plan.json` | 코치 계획 파일 (원두 예시, 권장 21만 원 = 네이버 6.8만 · 메타 14.2만, 10/1 시작) | 첫 화면·한 달 뒤 "계획 파일 불러오기" |
| `naver_report.csv` | 네이버 검색광고 다차원 보고서 항목 이름 △ (공식 양식 미확인) | 한 달 뒤 "광고 리포트로 다시 계산하기" |
| `meta_report.csv` | 메타 광고 관리자 한국어 내보내기 열 이름 ✅ (실제 내보내기 열) | 같은 곳 |
| `store_stats.csv` | 스마트스토어 통계처럼 일별 유입수·상품상세조회수·장바구니수·결제수·결제금액 | 한 달 뒤 "판매처 통계 파일", 로그 분석 탭 퍼널 |
| `orders.csv` | 커머스API "상품 주문 정보 구조체" 항목 이름 ✅ (`커머스API_주문데이터_매핑.md`) | 실제 주문 수 세기 (10월, 취소 제외) |

## 만든 방법 (가정)
- 판매가 2만 원, 남는 돈 7천 원(마진 35%), 상품 2개
- 광고 없이 하루 평균 3.5건(포아송), 그중 약 25%는 이전 손님의 재구매
- 10월 한 달 광고: 네이버 6.8만 원(클릭 1번 약 1,900원), 메타 14.2만 원(약 1,300원), 누른 사람 중 산 비율 약 1.3%(GA4 공개 샘플 수준)
- 메타 리포트 '결과'는 조회 후 구매·다른 경로 구매까지 세도록 실제 광고 주문보다 많게 넣음 → 과대 집계율 시연
- 네이버 리포트는 전환 추적이 빠진 가게처럼 전환 0 → "측정부터 확인" 진단 시연
- 주문의 유입 경로: 네이버 광고 = `검색광고(SA)`, 메타 광고 = `네이버 쇼핑 외` + `meta_paid_social`(유입 경로 추가 정보는 실제 값 미확인), 메타 손님 60%는 쿠폰 사용

## 시연 순서 (원두 예시)
1. 첫 화면 → "계획 파일 불러오기"에 `plan.json`
2. 한 달 뒤 단계에서 판매처 통계 파일에 `store_stats.csv`
3. "광고 리포트로 다시 계산하기"에 `naver_report.csv`, `meta_report.csv` → 실제 주문 수에 `orders.csv`의 10월 광고 주문 수
