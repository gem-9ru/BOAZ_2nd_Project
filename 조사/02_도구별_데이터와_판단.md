# 02. 도구별 데이터와 판단: 어떤 도구가 어떤 숫자를 주고, 그 숫자로 무엇을 정하나

> 조사일: 2026-11-05. 범위는 마케터가 쓰는 7개 도구 분류(①예산 계획 ②광고 집행 ③행동 분석 ④기여 측정 ⑤증분 측정 ⑥고객 재접촉 ⑦데이터 연결)입니다.
> 이미 정리된 내용(GA4 모델 축소, 메타 조회 기간 축소, 카카오 메시지 규정)은 [기능명세_4개도구.md](../기능명세_4개도구.md) 10-4를 따르고, 여기서는 반복하지 않습니다.
> 신뢰도: ✅ 공식 문서 본문을 직접 열어 확인 · △ 검색 요약이나 2차 자료로만 확인 · † 출처를 못 찾은 일반 지식.
> 블로그·대행사 자료는 출처에 **[업계 자료]** 로 표시했습니다.

---

## 0. 한눈에 보기

- **같은 구매도 도구마다 숫자가 다릅니다.** 기여 기간, 조회 인정 여부, 모델링, 날짜 기준이 도구마다 다르기 때문입니다. 그래서 우리 서비스는 "어느 도구의 숫자인지"와 "어떤 기준인지"를 숫자와 함께 받아야 합니다.
- **날짜 기준 차이가 가장 자주 놓치는 함정입니다.** 구글 광고의 기본 전환 열은 **클릭한 날**에 전환을 붙이고 ✅[2], GA4는 **전환한 날**에 붙입니다 ✅[9]. 월 단위로 보정하면 월말 클릭분이 다음 달로 넘어갑니다.
- **도구를 잇는 키는 거의 다 "클릭 1회" 단위입니다.** gclid·fbclid·UTM은 세션까지는 잇지만, 재구매·추천처럼 클릭 없이 일어나는 행동은 **사용자 ID·거래 ID**로만 이을 수 있습니다.
- **기여 측정(④)과 증분 측정(⑤)은 다른 질문에 답합니다.** 예산 이동 결정에는 증분 값이 맞지만, 대부분의 광고주는 기여 값만 가집니다. 메타 전환 상승 테스트는 담당자를 통해서만 쓸 수 있고 ✅[22], MMM은 주간 데이터 2~3년이 필요합니다 ✅[38].
- **우리 서비스의 입력 단위는 "채널 × 월(또는 주) × 지표 × 기준"** 으로 잡는 것이 현실적입니다. 사용자 단위 원자료는 GA4 BigQuery나 MMP가 있어야 받을 수 있습니다.

## 2. 같은 "전환"이 도구마다 다르게 세어지는 이유 (질문 2)

### 2-1. 원인 6가지

| 원인 | 무슨 일이 생기나 | 근거 | 신뢰도 |
|---|---|---|---|
| **① 기여 기간** | 클릭 후 며칠까지 전환으로 인정하는지가 다름. 기간이 끝난 뒤의 전환은 아예 기록되지 않고, 기간을 바꿔도 **앞으로의 데이터에만** 적용됨 | 구글 광고 클릭 30일(1~90일) ✅[3], 메타 API 기본 클릭 7일·조회 1일 ✅[18], GA4 유입 전환 30일·그 밖 90일 ✅[15], 에어브릿지 클릭 7일 ✅[35], 네이버 15일(7~20일) △[27] | 혼합 |
| **② 조회 기여** | 광고를 **보기만** 한 사람의 전환도 셈. GA4는 클릭해 들어온 세션 기준 | 구글 광고 조회 1일·참여 조회 3일 ✅[3], 메타 `1d_view` ✅[18], 에어브릿지 조회 1일 ✅[35] | ✅ |
| **③ 모델링된 전환** | 쿠키 동의 거부 등으로 안 보이는 전환을 **추정해서 더함.** 구글 광고는 이 값을 "전환" 열에 관측값과 합쳐 보여주고, 안정되기까지 최대 5일 | 구글 광고 도움말 [4]. GA4가 구글 광고로 보내는 것은 관측 전환이고, 모델링은 구글 광고가 따로 함 △[9 업계 요약] | △ |
| **④ 날짜 기준** | 구글 광고 기본 열은 **클릭한 날**, "전환 시점 기준" 열은 전환한 날 ✅[2]. GA4는 전환한 날 ✅[9]. 메타 API는 `action_report_time`으로 노출일·전환일·혼합 중 선택 ✅[18] | 구글은 "전환의 95% 이상이 14일 안에 귀속되니 14일 지난 데이터로 비교하라"고 안내 ✅[9] | ✅ |
| **⑤ 중복 집계** | 한 도구 안: 픽셀과 서버 전송(전환 API)이 같은 구매를 두 번 보낼 수 있음. 메타는 `event_id`+이벤트 이름이 같고 **48시간 안**이면 하나로 합침 ✅[20]. GA4는 같은 거래 ID 구매를 하나로 합치지만, 거래 ID를 빈 값으로 보내면 **모든 구매가 하나로 합쳐짐** ✅[10] | 여러 도구 사이: 각 매체가 자기가 닿은 구매를 모두 자기 것으로 보고 → **매체 합계 > 실제 구매** | ✅ / † |
| **⑥ 자기 참조** | 결제 대행사·로그인 페이지에서 돌아온 방문이 새 유입(referral)으로 잡혀 기여를 가져감. GA4 "원치 않는 추천 목록"으로 막음 | ✅[17], GA4 샘플에서 referral 접점의 65.2% (기능명세 4-2) | ✅ |
| (추가) 크레딧 대상 채널 | 2023년 6월 이후 만든 GA4 속성은 구글 광고로 보내는 전환의 기본 설정이 "구글 유료 채널"만. 설정에 따라 GA4 숫자가 달라짐 | ✅[9] | ✅ |

## 3. 도구 사이를 잇는 키 (질문 3)

| 키 | 누가 붙이나 | 무엇과 무엇을 잇나 | 끊기는 경우 | 신뢰도 |
|---|---|---|---|---|
| **UTM** (`utm_source`, `utm_medium`, `utm_campaign`, `utm_id`, `utm_term`, `utm_content`, `utm_source_platform`) | 마케터가 랜딩 URL에 직접 | 매체 캠페인 ↔ GA4 세션·전환. `utm_id`는 캠페인 데이터 업로드의 ID와 맞춰 비용을 붙일 수 있음 | **대소문자 구분**("Google"≠"google"). 빠지면 `(not set)`. `utm_creative_format`·`utm_marketing_tactic`은 아직 GA4 보고서에 안 나옴 | ✅[11] |
| **gclid** | 구글 광고 자동 태그 | 구글 광고 클릭 ↔ GA4 세션, 오프라인 전환 가져오기 | 자동 태그를 끄면 없음. GA4 BigQuery에 gclid는 있지만 iOS용 wbraid·gbraid는 없음 | ✅[1][7] |

| **NaPm** | 네이버 광고 클릭 URL에 붙는 값 | 네이버 광고 클릭 정보(여러 항목을 `|`로 이은 형태) ↔ 사이트 분석. 키워드 단위 측정에는 `n_keyword` 같은 별도 파라미터를 함께 씀 | **네이버 공식 정의를 찾지 못함.** 쇼핑검색광고는 파라미터 값을 바꾸면 사이트가 안 열릴 수 있음 | △[28] |
| **event_id** | 광고주(픽셀·서버 양쪽) | 메타 픽셀 이벤트 ↔ 전환 API 이벤트 (중복 제거용) | 48시간이 지나면 못 합침 | ✅[20] |
| **사용자 ID** | 광고주(로그인 시점) | 기기·세션을 넘어 같은 사람을 이음 → **재구매·리텐션 계산의 유일한 키** | 직접 만들어야 하고, 개인을 알아볼 수 있는 값은 금지, 256자 미만 | △[12] |
| **거래 ID** | 광고주(주문 번호) | GA4 구매 ↔ 쇼핑몰 주문·CRM·MMP. 중복 구매 제거 | 빈 값이면 모든 구매가 합쳐짐 | ✅[10] |
| **쿠폰 코드** | 마케터 | 메시지·인플루언서·오프라인 ↔ 주문. 클릭이 없는 접점(추천·입소문)을 셀 수 있는 거의 유일한 방법 | 코드가 공유되면 출처가 흐려짐 | † |
| **전용 링크(트래킹 링크·딥링크)** | MMP | 매체·메시지·추천 ↔ 앱 설치·인앱 이벤트. 에어브릿지는 트래킹 링크를 가장 높은 우선순위로 씀 | 앱이 없으면 의미 작음 | ✅[36] |
| **SKAN 캠페인 ID·전환 값** | 애플 → MMP | iOS 광고 ↔ 설치 후 행동(집계) | **사용자 단위로 못 이음.** 지연·익명성 단계에 따라 값이 비어 옴 | △[34] |

**정리: 키가 닿는 범위**

```
노출 ──(조회 기여: 매체 내부만)──┐
클릭 ──(gclid · fbclid · NaPm · UTM)──> 세션 ──(사용자 ID)──> 구매 ──(거래 ID)──> 주문·CRM
                                                    └──(사용자 ID)──> 재구매
메시지 ──(UTM · 전용 링크 · 쿠폰)──> 세션/구매              추천 ──(쿠폰 · 추천 링크)──> 신규 구매
```

- 매체 클릭 ID는 **첫 구매까지**만 책임집니다. 재구매와 추천은 광고주 쪽 키(사용자 ID, 거래 ID, 쿠폰)가 있어야 셀 수 있습니다 †.

### 6-1. 입력 칸

| **기여 기간** | 선택: 클릭 1·7·28·30일, 조회 0·1일, 기타 | 메타·구글·네이버 기본값이 다름 (2-2) |
| **날짜 기준** | 선택: 클릭(노출)일 / 전환일 | 구글 기본 열은 클릭일, GA4는 전환일 ✅[2][9] |
| **전환 정의** | 선택: 구매 / 장바구니 / 가입 / 상담 등 | 네이버도 전환 유형을 나눠 보고 ✅[25] |

| **증분 결과 (선택)** | 증분 전환, 신뢰구간 하한·상한, 실험 기간 | 전환 상승 결과 형식 그대로 ✅[22] |
| **데이터 준비 체크** | 예/아니오: UTM 규칙, 자동 태그(gclid), 거래 ID, 사용자 ID, 원치 않는 추천 설정, 픽셀+서버 중복 제거 | 3장의 키가 있어야 4·5장 판단이 가능. 기능명세 10-1의 "측정 준비"를 구체화 |

### 6-2. 업로드 양식 (월 예산 루프용 표준 CSV)

**A. 매체 성과 (채널 × 기간)** — 매체 CSV를 이 열로 매핑
```
period_start, period_end, channel, campaign, spend, impressions, clicks,
conversions, conversion_value, attribution_window, date_basis, source
```
- 매핑 예시: 네이버 `salesAmt→spend, impCnt→impressions, clkCnt→clicks, ccnt→conversions, convAmt→conversion_value` ✅[24]. 구글 `cost_micros ÷ 1,000,000 → spend` △[5]. 카카오 구매 1일/7일 필드 중 하나 선택 △[30]. 메타 `actions`에서 구매 행동만 추출 ✅[18].
- 카카오는 한 번에 31일까지라 **월 단위로 나눠 받기** 안내 ✅[29].

**B. 분석 도구 퍼널** — 기존 기능명세 3-1 양식(`segment, step_1_users … step_n_users`) 유지 + `unit`(사용자/세션), `funnel_type`(열린/닫힌) 열 추가.

**C. 주문 이력 (자사)** — 재구매·추천 계산용
```
order_id, user_id, order_date, revenue, first_touch_channel(선택), coupon_code(선택)
```
- `order_id`는 GA4 거래 ID와 같은 값이면 매체·GA4와 대조 가능 ✅[10].

**D. 경로 (선택)** — 기존 기능명세 4-1 양식 유지.

### 6-3. 보정 규칙

1. **매체 합계 점검**: `Σ 매체 보고 전환 ÷ 자사 실제 구매`가 1보다 크면 "매체 간 중복 집계 가능성" 경고. 이 비율을 **중복 계수**로 저장하고, 다음 달 매체 보고값을 나눠 쓰는 기본값으로 제안 †.
2. **기간 맞추기**: 비교 대상끼리 기여 기간·조회 포함 여부가 다르면 비교표를 회색 처리하고 "같은 기간으로 다시 받으세요" 안내. 메타는 `1d_click`·`7d_click` 열을 따로 받을 수 있음 ✅[18].
3. **성숙 대기**: 클릭일 기준 데이터는 기간 종료 후 **14일 지나서** 확정치로 취급. 그 전 값은 "잠정"으로 표시 ✅[9]. GA4는 최소 48시간 뒤 ✅[8], 카카오는 다음 날 오전 8시 뒤 ✅[29].
4. **월 경계 보정**: 날짜 기준이 클릭일인 데이터와 전환일인 데이터를 섞지 않음. 섞이면 경고만 하고 합치지 않음.
5. **증분 우선**: 같은 채널에 증분 결과가 있으면 엔진의 `cvr_mult`는 기여 값 대신 **증분 값 기준**으로 보정하고, 신뢰구간 하한·상한으로 배분 범위를 함께 보여줌 ✅[22]. 없으면 "기여 기준(인과 아님)" 배지.
6. **모델링 전환 표시**: 구글 광고 숫자에는 추정 전환이 섞여 있을 수 있다는 도움말 문구. 최근 5일 값은 아직 바뀔 수 있음 △[4].
7. **재구매·추천은 자사 데이터로만**: 매체 보고값으로 리텐션을 채우지 않음. 주문 이력(C)이 없으면 엔진 기본값을 쓰고 "가정"으로 표시.
8. **MMM은 범위 밖, 결과만 받기**: 사용자가 Meridian·Robyn 결과(채널 ROI)를 가지고 있으면 선택 입력으로 받아 비교만 함. 우리 서비스가 MMM을 돌리지는 않음(데이터 2~3년 필요 ✅[38]).

## 7. 확인하지 못한 항목

- **네이버 검색광고 전환 추적 기간(기본 15일, 7~20일)과 직접·간접 전환 30분 기준**: 대행사 자료로만 확인 △[27]. 네이버 공식 도움말 미확인. 전환을 클릭일·전환일 중 어디에 붙이는지도 못 찾음.
- **NaPm 파라미터의 공식 정의**: 업계 자료에서 형태만 확인 △[28].
- **카카오모먼트 전환의 조회 기여 여부와 날짜 기준**: 공식 문서에서 못 찾음.
- **AppsFlyer 도움말 본문**: 자동 수집이 막혀(403) 검색 요약으로만 확인 △[33].
- **메타 전환 상승 최소 예산·전환 수**: 업계 자료끼리 숫자가 달라 쓰지 않음. 공식 문서에는 "분류별 결과는 전환 100건 이상"만 있음 ✅[22].
- **메타 API `action_report_time` 기본값**과 `default` 기여 기간의 문서 내 충돌 ✅[18] — 실제 계정으로 호출해 확인 필요.
- **"매체 ROAS 합 > 실제 매출"** 은 원리상 명확하지만 이를 직접 서술한 공식 문서는 찾지 못함 †.
