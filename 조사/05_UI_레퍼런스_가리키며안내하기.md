# UI 레퍼런스: 가리키며 안내하기 (REA 분석, 2026-11-16)

> 목적: 우리 화면(왼쪽 작업판 + 오른쪽 채팅 + 칸을 가리키는 캐릭터)과 비슷하게 **화면 요소를 가리키며 단계별로 안내하는** 서비스의 동작 방식을 배운다.
> 대상: 로그인 없이 공개된 **오픈소스(MIT) 안내 투어 라이브러리의 공식 데모** 두 곳. 코드·디자인 자산은 가져오지 않고 **동작 패턴만** 정리한다.
> 도구: REA(Reverse Engineer Anything) `capture_browser_scenario` — 임시 프로필 크롬으로 페이지를 열고, 버튼을 눌러 투어를 띄운 뒤 DOM·접근성 트리를 받음.

## 1. Driver.js (https://driverjs.com/, MIT)
'Show Progress' 데모를 눌러 1단계가 떴을 때의 구조:

| 요소 | 관찰한 구조 | 뜻 |
|---|---|---|
| 스포트라이트 | 화면 전체 고정 SVG 한 장(`position: fixed`, z-index 10000). 경로 = 바깥 사각형 + 대상 모양의 둥근 사각형 구멍(`fill-rule: evenodd`), 검정 70% | 대상만 밝고 나머지는 어둡게. 대상 밖 클릭은 막을 수 있음 |
| 말풍선 | `role="dialog"`, `aria-labelledby`(제목), `aria-describedby`(설명). 대상 아래쪽에 붙고(`side-bottom`, `align-start`), **대상을 가리키는 화살표**가 위치 계산으로 붙음 | 무엇을 보는지 제목·설명으로 말해 줌 |
| 아래 영역 | **"1 of 3" 진행 표시** + 이전(첫 단계 비활성) / 다음 버튼, 닫기 × | 지금 위치와 남은 단계 |
| 알림 | 화면에 안 보이는 `aria-live="polite"` 영역 | 단계가 바뀌면 화면 읽기 프로그램이 읽어 줌 |

## 2. Shepherd.js (https://shepherdjs.dev/, MIT)
홈 화면 설명과 예시 코드에서 확인:
- **키보드 이동, 포커스 가두기, aria 속성**을 기본 기능으로 내세움
- 대상으로 **부드럽게 가운데 스크롤** (`scrollTo: { behavior: 'smooth', block: 'center' }`)
- 말풍선을 대상의 어느 쪽에 붙일지 지정 (`attachTo: { element, on: 'bottom' }`)
- 단계마다 뒤로·다음 버튼, 닫기 아이콘

## 3. 우리 화면과 비교

| 항목 | 레퍼런스 | 우리 (v2, 11/16) | 개선 |
|---|---|---|---|
| 대상 강조 | 나머지를 어둡게(스포트라이트) | 대상에 3px 테두리만 | 작업판 안에서만 나머지 칸을 흐리게(채팅은 건드리지 않음) |
| 가리키는 것 | 화살표 달린 말풍선(제목+설명) | 작은 캐릭터 + "이 칸에 들어가요" | 캐릭터를 키우고, 말풍선에 **칸 이름 + 진행(3/12)** + 대상 쪽 화살표 |
| 진행 표시 | 말풍선 안 "1 of 3" | 채팅 쪽에만 | 말풍선에도 같은 숫자 |
| 스크롤 | 부드럽게 가운데 | 가운데 스크롤(있음) | 화면 밖일 때만, 부드럽게 |
| 접근성 | dialog·aria-live·키보드 | 없음 | `aria-live`로 "지금: 종료 날짜 칸" 알림, 캐릭터는 장식(`aria-hidden`) |
| 끄기 | 닫기 × | '캐릭터 보이기' 토글 | 유지 |

## 4. 하지 않는 것
- 화면 전체를 덮는 어두운 막: 오른쪽 채팅까지 가려서 우리 화면(채팅으로 답해야 함)에 맞지 않음
- 대상 밖 클릭 막기: 사장님이 작업판 다른 칸을 자유롭게 봐야 함
- 라이브러리 자체 도입: Streamlit은 화면을 다시 그릴 때마다 DOM이 바뀌어 외부 투어 라이브러리와 충돌함. 패턴만 CSS로 구현
