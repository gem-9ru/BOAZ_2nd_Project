# 04. 광고 방법별 산출 데이터와 고객 체인 연결

> 작성 2026-11-05 · 조사 주제: "광고 방법별로 집행하면 실제로 어떤 숫자를 돌려받고, 그 숫자가 체인 어디에 연결되는가"
> 함께 볼 문서: `광고_형태_비즈니스_리스트업.md` 3-1(과금 유형 7개), `기능명세_4개도구.md` 2장(M1), 5장(M4)
> 신뢰도: ✅ 공식 문서 본문 확인 / △ 2차 자료(업계 자료·보도)로만 확인 / † 출처 못 찾은 일반 지식
> 출처 번호 [n]은 문서 끝 "출처" 절에 있습니다.

## 0. 한 장 요약

- 매체가 돌려주는 숫자는 대부분 **①접촉·②반응**까지입니다. ③행동·④구매는 픽셀·전환 API를 깔아야 나오고, **⑤재구매·⑥추천은 어느 매체도 주지 않습니다.**
- 과금 유형별로 "돈을 내는 지점"과 "숫자가 끝나는 지점"이 다릅니다. A는 ②에서 내고 ④까지 볼 수 있습니다. D는 ④에서 내지만 ①②가 비어 있습니다. C·G는 체인 어디에서도 돈을 내지 않아 **모든 구간이 비기 쉽습니다.**
- 빈 구간은 **UTM·전용 랜딩·쿠폰 코드**로 ③④를, **주문 DB 코호트**로 ⑤를, **추천 코드**로 ⑥을, **브랜드 검색량**으로 C의 ①을 간접 측정해 메웁니다.
- 비교할 때 가장 큰 함정은 **중복 집계**입니다. 매체마다 자기 기준(클릭 후 n일, 조회 후 1일 등)으로 구매를 가져가므로 합이 실제 주문보다 큽니다. **주문 DB 총합을 기준값으로 두고 비례 축소**하는 것을 기본 규칙으로 제안합니다.

## 1. 기본 틀

### 1-1. 고객 체인과 대표 지표

| 지점 | 뜻 | 대표 지표 (매체 용어) |
|---|---|---|
| ① 접촉 | 광고·콘텐츠를 봤다 | 노출, 도달, 발송, 조회(시청) |
| ② 반응 | 눌렀다·봤다·열었다 | 클릭, 링크 클릭, 열람, 참여 |
| ③ 행동 | 사이트에서 의미 있는 행동 | 방문(세션), 장바구니, 가입, 미션 완료, 앱 설치 |
| ④ 구매 | 첫 구매 | 구매 수, 구매 금액, ROAS |
| ⑤ 재구매 | 두 번째 이후 구매 | (매체 지표 없음) 주문 DB 코호트 |
| ⑥ 추천 | 다른 사람을 데려옴 | (매체 지표 없음) 추천 코드 사용, 공유 |

### 1-2. 숫자를 받는 곳 4가지

| 출처 | 무엇이 오나 | 주기 | 특징 |
|---|---|---|---|
| 매체 리포트 | 비용·노출·클릭·매체 기준 전환 | 일 단위. 카카오모먼트는 당일 데이터를 다음 날 확인 [12] ✅ | 자기 매체 기준 기여. 다른 매체와 겹침 |

| GA4 | 세션, 이벤트, 구매 (UTM 기준 출처) | 실시간~1일 † | 모든 채널을 한 기준으로 봄. 기본 기여 기간: 유입 30일, 그 밖 90일 [6] ✅ |

## 2. 과금 유형별 받는 지표

| 전환수 `ccnt`, 전환매출 `convAmt`, `ror`, `cpConv`, 구매 전환 `purchaseCcnt` | 전환 스크립트로 잡힌 전환 | 건, 원, % | 같음 [18] ✅. 전환 스크립트 설치 필요 [20] △ | ③④ |

## 3. 핵심 매트릭스: 과금 유형 × 체인 지점

표기: **받음** = 매체·정산이 직접 줌 / **빔** = 아무도 안 줌 / **메움** = 메우는 방법

| 유형 (돈 내는 지점) | ① 접촉 | ② 반응 | ③ 행동 | ④ 구매 | ⑤ 재구매 | ⑥ 추천 |
|---|---|---|---|---|---|---|
| **A 클릭당** (②) | 받음: 노출·순위 [18] | 받음: 클릭·CPC [18] | 받음(스크립트 설치 시): 전환수 [18] | 받음: 전환매출. 쿠팡 간접 전환 부풀림 주의 [23] | **빔** → 메움: UTM `utm_term` + 주문 DB 코호트 | **빔** → 추천 코드 |
| **B 노출·시청당** (①) | 받음: 노출·도달(추정) [10][11] | 받음: 링크 클릭·조회·재생 [1][12] | 받음: 픽셀 이벤트 [12] | 받음(기여 기간 안): 결과·VTC(보고 전용) [2][7] | **빔** → 주문 DB 코호트 (UTM `utm_campaign`) | **빔** |
| **C 고정비** (계약) | 일부: 브랜드검색 노출, 인플루언서 **캡처** [9] | 일부: 브랜드검색 클릭, 캡처 | **빔** → 전용 랜딩 + UTM | **빔** → 전용 쿠폰 코드 | **빔** → 쿠폰 사용 고객 코호트 | **빔** |
| **D 판매 연동** (④) | **빔**(캡처만) [9] | 일부: 파트너스 클릭 [22] | **빔** | 받음: 정산 판매 수·매출 | **빔** → 공구 구매자 고객 ID를 주문 DB로 (자사몰 판매일 때만) | **빔** |
| **E 행동당** (③) | 받음: 노출 † | 받음: 참여 † | 받음: 미션 완료 † | 일부: 픽셀 전환(불일치) [25] | **빔** → 주문 DB 코호트 | **빔** |
| **F 발송당** (①) | 받음: 발송수 [13] | 받음: 열람·클릭 [13] | 받음: 장바구니 [13] | 받음: 구매 [13] (실제로는 ⑤) | 일부: 매체 구매 = 재구매. **증분은 대조군 필요** | **빔** (공유 버튼 클릭만) [13] |
| **G 직접비** (체인 밖) | 일부: 게시물 수, 캡처 | **빔** → UTM | **빔** | **빔** → 리뷰 노출 전후 전환율 | **빔** | 받음(간접): 리뷰 수 = ⑥ |

**읽는 법**
- 돈 내는 지점 **앞쪽**은 비기 쉽습니다(D의 ①②). 매체가 그 앞을 셀 이유가 없기 때문입니다 †.
- 돈 내는 지점 **뒤쪽**은 매체 픽셀이 있을 때만 ④까지 이어지고, ⑤⑥은 모든 유형에서 비어 있습니다.
- 그래서 ⑤⑥은 매체가 아니라 **우리 도구의 주문 DB 업로드**로만 채울 수 있습니다. 기획안의 "ROAS만 보면 뒤 단계가 안 보인다"를 데이터 구조로 확인한 셈입니다.

## 4. 빈 구간을 메우는 실무 방법

| 방법 | 무엇을 메우나 | 어느 유형에 | 어떻게 | 한계 |
|---|---|---|---|---|
| **UTM** | ③④ (GA4에서 채널 구분) | 전부, 특히 C·D·G | `utm_source`·`utm_medium`·`utm_campaign`은 항상 넣음. `utm_content`로 소재 구분, `utm_id`로 캠페인 ID [3] ✅ | 앱 내 브라우저·캡처 공유에서 끊김 †. 쿠팡 등 외부 몰 판매는 못 봄 |
| **전용 랜딩** | ③ | C·G | 인플루언서·박람회마다 별도 URL. 방문 수가 C의 "분모" | 사람이 직접 주소를 치면 놓침 † |
| **쿠폰 코드** | ④⑤ | C·D·G | 채널별 고유 코드. GA4 `purchase` 이벤트 `coupon` 매개변수에 기록 [5] ✅, 주문 DB에도 남음 | 쿠폰 공유 사이트로 유출 † |
| **프로모 링크·추천 코드** | ⑥ | 전부 | 고객별 추천 코드 → 신규 주문에 코드 기록 † | 말로 추천한 것은 못 봄 |
| **매체 전환 API** | ③④ 누락 감소 | A·B·E | 메타 Conversions API: 픽셀과 같이 보내면 `event_id`+`event_name`이 48시간 안에 일치할 때 중복 제거 [8] ✅. 카카오 Conversion API: 서버 전송, 픽셀과 중복은 카카오가 제거. 현재 비즈보드·디스플레이만 측정 [16] ✅. 카카오 클릭 ID `kclid`: 1자 쿠키로 저장해 전환과 연결 [17] ✅ | 매체 기준 기여라 매체 간 중복은 그대로 |
| **비용 데이터 가져오기** | 비용을 GA4로 | C·D·G 등 매체 연동 없는 채널 | GA4 캠페인 데이터 가져오기: 필수 `utm_source`·`utm_medium`·날짜, 권장 `utm_id`·`utm_campaign`, 비용·클릭·노출 중 1개 이상 [4] ✅ | 손으로 올려야 함 |
| **브랜드 검색량** | C·B의 ① 인지 효과 | C (브랜드검색, 원고료, 박람회), B | 키워드 도구 월간 검색수(30일 합, 절대값) [18] ✅로 집행 전후 비교. 데이터랩은 상대값이라 **같은 조회 안에서만** 비교 [21] △ | 계절·다른 광고 영향 섞임 † |
| **판매 정산 데이터** | D의 ④ 확정값 | D | 정산서 판매 수·취소·수수료를 그대로 업로드 † | 외부 몰 고객 ID가 없어 ⑤ 연결 불가 |
| **주문 DB 코호트** | ⑤ | 전부 | 첫 구매 채널(UTM·쿠폰)별로 1·2·3개월 재구매율 † | 첫 구매 채널 태깅이 전제 |
| **대조군(홀드아웃)** | 증분 | F, B | 대상 일부를 안 보내고 차이를 봄 (M4 5-4). 메타 전환 상승 측정도 같은 구조 [26] △ | 표본이 작으면 오차 큼 |

## 6. 엔진 입력으로 바꾸는 규칙 (유형별)

공통 기호: 비용 `S`, 노출 `I`, 클릭 `K`, 방문(세션) `V`, 구매 `P`, 매출 `R`, 객단가 `AOV = R/P`.
엔진이 받는 값: **클릭당 비용 곡선**(`curve`), **전환율 배수**(`cvr_mult`), **재구매 배수**(`retention_mult`) (기능명세 2장).

| 유형 | 받은 숫자 | 변환 규칙 | 엔진 입력 |
|---|---|---|---|
| A | `S`, `K`, `P`(매체) | `CPC = S/K`. 월별 (예산, 클릭) 점을 모아 곡선. 네이버 예상 실적은 28일 기준이라 ×30.4/28 [19] | `curve` |
| A | GA4 `V`, 주문 DB `P` | `CVR_ch = P_DB / V`. `cvr_mult = CVR_ch ÷ 사이트 평균 CVR` | `cvr_mult` |
| B | `S`, `I`, 링크 클릭 `K` | `CPM = 1000·S/I`, `CTR = K/I`, **`CPC_eff = CPM ÷ (1000·CTR)`** | `curve` (CPC로 환산) |
| B (유튜브 CPV) | `S`, 조회 `W`, `K` | `CPV = S/W`, `CPC_eff = CPV ÷ (K/W)` | `curve` |
| B | 도달 `U`, `I` | 빈도 `F = I/U`. 빈도가 오르는데 CTR이 내리면 소재 피로 경고 † | 경고만 |
| C | 고정비 `F_c`, 전용 랜딩 `V_c`, 쿠폰 주문 `P_c` | `CPV_c = F_c / V_c`, `CPA_c = F_c / P_c`. **쪼갤 수 없음** → 0/1 선택지 | 새 유형 `fixed(cost, visits, cvr)` |
| C (인지) | 브랜드 검색수 전 `Q0`, 후 `Q1` | 증분 검색 `ΔQ = Q1 − Q0`(계절 보정 †). 브랜드 키워드 CTR·CVR을 곱해 추가 구매로 환산 | 참고값 (본 계산에 안 넣음) |
| D | 판매 수 `P_d`, 매출 `R_d`, 수수료율 `c`, 착수금 `F_d` | `구매당 비용 = c·AOV + F_d/P_d`. 비용은 매출에 비례하므로 곡선이 아니라 **비율**. 상한 = 1회 판매량 | 새 유형 `rev_share(c, fixed, cap)` |
| D (파트너스) | 클릭 `K`, 주문 `P` | `CVR_24h = P/K` (24시간 기준이라 다른 채널보다 낮게 나옴 [22]) | 참고값 |
| E | 행동 수 `M`, 행동 단가 `p`, 구매 `P_e` | `행동→구매율 a = P_e/M` (쿠폰·전용 랜딩으로 측정). `구매당 비용 = p / a` | 새 유형 `per_action(p, a)` |
| F | 발송 `N`, 단가 `u`, 대조군 구매율 `r0`, 발송군 `r1` | 증분 반응률 `Δr = r1 − r0`, 손익분기 `r* = u ÷ (AOV·(1−할인)·마진)` (M4 5-3) | M4 시나리오 |
| G | 직접비 `C_g`, 전후 전환율 `CVR0→CVR1` | 레버 효과 `ΔCVR`. 순이익 = ΔCVR × 방문 × AOV × 마진 − `C_g` | 활성화 레버 + 비용 |
| 공통 ⑤ | 주문 DB 첫 구매 채널별 재구매율 `ret_ch(t)` | `retention_mult = ret_ch(t) ÷ ret_all(t)` (t=1~3개월) | `retention_mult` |
| 공통 ⑥ | 추천 코드 신규 주문 | `추천율 = 추천 신규 / 채널 첫 구매자` | 추천 단계 |

**규칙의 원칙**
1. 매체 전환은 **곡선 모양(비용→클릭)** 에만 쓰고, 전환율·재구매율은 **주문 DB·GA4**에서 가져옵니다. 매체마다 기여 기준이 달라서입니다.
2. 측정값이 없는 칸은 **비워 두고** 손익분기값만 보여 줍니다 (M4 5-2와 같은 원칙).
3. 모든 숫자에 "출처(매체/정산/GA4/DB)"와 "기간"을 같이 저장합니다.

## 7. 서로 다른 방법을 같은 자로 비교할 때의 문제

| 문제 | 무엇이 생기나 | 예 | 정규화 방법 |
|---|---|---|---|
| **중복 집계** | 매체 전환 합 > 실제 주문 | 메타(클릭 7일)·네이버·카카오가 같은 주문을 각자 셈 † | 월 주문 DB 총합을 기준으로 **매체 전환을 비례 축소**: `P_ch' = P_ch × (P_DB / ΣP_ch)`. 또는 GA4 한 기준(마지막 클릭·데이터 기반)으로 통일 [6] |
| **조회 기여** | 클릭 없는 전환이 섞임 | 메타 조회 후 1일 [7], Google VTC [2] | 기본 비교는 **클릭 기여만**. 조회 기여는 별도 칸 "참고"로 |
| **기여 기간 차이** | 같은 성과가 다르게 보임 | 쿠팡파트너스 24시간 [22] vs GA4 30·90일 [6] vs 네이버 최대 20일 [20] | 기간을 화면에 표기. 비교는 GA4 단일 기간 또는 주문 DB 쿠폰 기준 |
| **집계 기준일** | 반응일 기준 vs 전환일 기준 | 네이버는 광고 반응일 기준 집계 [20] △ | 월말 집계를 다음 달 7일 이후 확정 † |
| **기간 단위** | 28일 vs 30일 vs 달력 월 | 네이버 예상 실적 28일 [19], 키워드 도구 30일 [18] | 하루 평균으로 바꾼 뒤 ×달력 일수 |
| **취소·반품** | 리포트 매출 > 정산 매출 | 쿠팡파트너스 취소 제외 [22] | **순매출(취소 반영)** 로 통일. D는 정산서, 나머지는 주문 DB |
| **부가세** | 비용이 1.1배 차이 | 카카오 보고서 VAT 제외 [12] | 모든 비용을 VAT 제외로 통일 † |
| **단위 차이** | 사람 vs 횟수 | 도달(사람·추정) vs 노출(횟수), 인스타 views는 반복 재생 포함 [9] | ①은 **노출(횟수)** 로만 비교. 도달은 빈도 계산용 |
| **추정치** | 도달은 표본 추정 | 메타 도달 [10], 인스타 reach [9] | 합산 금지 (매체 간 도달을 더하지 않음) |
| **증분 아님** | 어차피 살 사람까지 셈 | 브랜드검색, 리타기팅, F 메시지 † | 가능하면 대조군·전후 비교. 안 되면 "기여(증분 아님)" 표시 (기능명세 10-3) |
| **판매처 차이** | 외부 몰 판매는 우리 DB에 없음 | 쿠팡파트너스·라이브·공구(외부몰) | D는 정산 판매 수를 ④로 쓰고 ⑤는 "측정 불가"로 둠 |

**최종 비교 자**: "**월 순매출 기준 구매 1건당 비용(VAT 제외)**"과 엔진의 "**12개월 남는 돈**". 앞의 것은 측정값, 뒤의 것은 예측값으로 구분해 표시합니다.

## 8. 우리 서비스에 반영할 점

### 8-1. 채널 카드 입력 칸 (과금 유형별)

| 유형 | 필수 칸 | 선택 칸 | 자동 계산 |
|---|---|---|---|
| A | 월 비용, 클릭 | 노출, 매체 전환, 평균 순위 | CPC, CTR, 곡선 점 추가 |
| B | 월 비용, 노출, 링크 클릭 | 도달, 조회(유튜브), 매체 전환(클릭 기준만) | CPM, CTR, **CPC_eff**, 빈도 |
| C | 계약 비용, 기간, **전용 URL 또는 쿠폰 코드** | 캡처한 조회·도달, 브랜드 검색수 전후 | 방문당 비용, 구매당 비용 |
| D | 수수료율, 착수금, 정산 판매 수·순매출 | 클릭(파트너스), 캡처 도달 | 구매당 비용, 실효 수수료율 |
| E | 행동 단가, 행동 수, **전용 쿠폰 또는 랜딩** | 매체 전환 | 행동→구매율, 구매당 비용 |
| F | 건당 단가, 발송 수, 대상 그룹 | 열람·클릭, 대조군 구매율 | 손익분기 반응률, 증분 반응률 |
| G | 들인 비용(원가·배송·수수료·적립금), 기간 | 게시물 수, 리뷰 수 | 전후 전환율 차이, 순이익 |

- 모든 카드에 **"측정 출처" 선택**(매체/정산/GA4/주문 DB/캡처/추정)과 **"기여 기준" 선택**(클릭 n일/조회 1일/24시간/정산)을 둡니다.
- C·D·E·G 카드는 저장할 때 **"UTM 링크·쿠폰 코드를 만들었나요?"** 체크를 강제합니다. 없으면 다음 달 보정에서 ③④가 0으로 나온다고 경고합니다.
- 카드 하단에 체인 막대 ①~⑥를 그리고, 받은 칸은 진하게, 빈 칸은 점선, 메운 칸은 "UTM/쿠폰/DB" 배지로 표시합니다.

### 8-2. 업로드 양식 (다음 달 보정용)

**(1) 채널 실적 CSV** — 매체 리포트·정산서를 한 양식으로

| 열 | 형식 | 예 | 비고 |
|---|---|---|---|
| `month` | YYYY-MM | 2026-11 | 달력 월 |
| `channel_id` | 문자 | naver_pl, meta, yt_instream, kakao_bm, gongu_A | 64개 목록 번호와 연결 |
| `billing_type` | A~G | B | |
| `cost_ex_vat` | 원 | 1,200,000 | VAT 제외 |
| `impressions`, `reach`, `views`, `clicks`, `sends`, `opens` | 정수 | | 해당하는 것만 |
| `actions` | 정수 | | E 미션, 장바구니 등 |
| `platform_purchases`, `platform_revenue` | 정수, 원 | | 매체·정산 기준 |
| `attribution_rule` | 문자 | click_7d, view_1d, 24h, settlement | 기여 기준 |
| `source` | 문자 | platform, settlement, capture | |
| `utm_campaign`, `coupon_code` | 문자 | | 주문 DB 연결 키 |

GA4 캠페인 데이터 가져오기 형식 [4]과 맞추면 같은 파일을 GA4에도 올릴 수 있습니다 (`utm_source`, `utm_medium`, `utm_campaign`, `utm_id`, 날짜, 비용, 클릭, 노출).

**(2) 주문 CSV** — ⑤⑥을 위한 최소 열

`order_id, order_date, customer_id(해시), net_revenue, is_first_order, utm_source, utm_medium, utm_campaign, coupon_code, referral_code, canceled`

- `customer_id`는 해시만 받습니다 (카카오 Conversion API도 해시 식별자만 허용 [16]).
- 첫 구매 주문의 UTM·쿠폰으로 고객의 "획득 채널"을 정하고, 이후 주문으로 `retention_mult`를 계산합니다.

**(3) 캡처 입력 칸** — 인플루언서·체험단: 게시 URL, 게시일, 캡처일(게시 후 3일 이후 권장, 지연 최대 48시간 [9]), 조회·도달·저장·공유.

### 8-3. 변환 규칙 (엔진 코드 반영)

1. **B → A 변환 함수**: `cpc_eff = cpm / (1000 * ctr)`, 유튜브는 `cpv / (clicks/views)`. 메타 고급 설정과 같은 식 (기능명세 2장).
2. **새 채널 유형 3개**: `fixed`(C), `rev_share`(D), `per_action`(E). 리스트업 3-4의 제안 순서(B → D → C → E·G)를 따릅니다.
3. **중복 보정 계수**: `dedup = P_DB / Σ platform_purchases`를 매달 계산해 화면에 보여 줍니다. 1보다 많이 작으면 "매체 전환이 겹칩니다" 경고.
4. **전환율·재구매 배수는 주문 DB 우선**: DB가 없을 때만 매체 전환을 쓰고 "매체 기준" 배지를 붙입니다.
5. **조회 기여 분리**: `attribution_rule`이 view로 시작하면 본 계산에서 빼고 참고 칸에만 보여 줍니다.
6. **월 정렬**: 28일·30일 값은 하루 평균 × 달력 일수로 바꿉니다.
7. **빈 칸은 비움**: 측정 없는 전환율에 기본값을 넣지 않고, 손익분기값만 보여 줍니다.
