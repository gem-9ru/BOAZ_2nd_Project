# 프로토타입 개선 계획: 노션 기획(11/9) 맞추기

Ticket: 노션 팀 페이지 "광고 예산 코치" 개정본 (11/9, 사용자 공유)
실행: 프로토타입 개발 세션 (구현), 기획 세션 (검증·문서)
상태: **승인됨 (11/9, 사용자 "승인, 시작") — 실행 중**

## 0. 노션 기획 vs 지금 앱 (차이 요약)

| 노션 기획 | 지금 앱 (v0.9.x, main 77fd561) | 차이 |
|---|---|---|
| 매체: **네이버 검색광고 + 메타** 두 개, 예산을 둘에 **나눔** (Q1) | 코치는 판매처별 첫 채널 **하나**(쿠팡·플레이스 포함). 둘 사이 배분은 다음 단계 "광고 관리자" 탭에만 | 코치에 네이버·메타 배분이 없음 |
| 결과를 **이익 범위와 이익 날 확률**로 (Q2) | 숫자 하나(손님 1명 한도, 필요 구매 비율 → 신호등) | 몬테카를로 시뮬레이션 없음 |
| **손익분기 재구매율 지도** (Q3: 객단가 × 재구매율) | 재구매 프리셋 3개 → 1년 손익분기 숫자 하나 | 지도 없음 |
| 한 달 뒤 **네이버·메타 리포트 CSV 업로드** → 컬럼 진단, **플랫폼 과대 집계율**, **예측 오차율** (Q4) | 숫자 3개 직접 입력 + 판매처 통계 파일. 리포트 CSV는 다음 단계 시작 탭의 범용 CSV뿐 | 리포트 매핑·진단 규칙·과대 집계율·예측 오차 없음 |
| **데이터 신뢰 등급 A~D**를 모든 숫자에 | "가정값", "참고 기준", 출처 캡션이 곳곳에 | 등급 체계 없음 |
| **챗봇 대화**가 입구 (Track 2, LLM API) | 질문 폼 + 규칙 기반 도우미(💬) | LLM 대화 입력 없음 |
| **광고 관리자 가이드**: 메타 목적(인지도·트래픽), 자동 vs 수동 | 없음 (학습 단계 경고만) | 신규 |
| **시연용 가상 주문·유입 데이터**, 생성 방법 명시 | 없음 (커머스API 구조 문서만) | 신규 |
| 예시: 원두 로스터리, **객단가 2만·마진 35%·월 30만** | 예시: 원두 3.5만·남는 돈 1.4만·월 100만 | 예시 숫자 교체 |
| 한 달 뒤 다시 와야 함 | 입력이 세션에만 있어 새로고침하면 사라짐 | 저장·불러오기 필요 (Q4 전제) |

그대로 쓰는 것: 엔진(12개월 코호트, 네이버 볼록 곡선, 메타 Hill 곡선, `optimize_allocation`), 손익분기 CPA, 판정 순서, 측정 키트(NT·UTM·쿠폰), 계절성, 밸류체인, UX 설계 원칙.

> 실행 순서 (사용자 결정): Phase 1 → 2 → 4 → 3 → 5 → 6 → 7 → 8

## Phases

### Phase 1: 예시·범위 정리와 네이버·메타 배분 (Q1)
Verified when: 원두 예시(2만·35%·30만)로 코치 답 보기에 "네이버 ○만 · 메타 ○만" 배분과 근거(키워드 포화 지점)가 나온다.
Files to touch: `app/main.py`(코치 단계 2·3), `src/engine/coach.py`, `src/engine/optimize.py`(재사용), `src/engine/defaults.py`, `tests/test_coach.py`

#### Step 1.1: 예시 페르소나 교체 (Size: XS)
- Acceptance: "예시로 먼저 보기" = 스마트스토어 원두, 판매가 2만, 마진 35%(남는 돈 7,000원), 월 30만, 재구매 '가끔', 검색어 '원두커피'
- Verification: `.venv/bin/python -m pytest tests/test_coach.py -q` + 배포 앱 예시 화면
- Blocked by: none

#### Step 1.2: 코치 Q1 — 네이버·메타 예산 배분 (Size: M)
- Acceptance: 코치 단계 3의 "첫 채널 하나"를 "네이버 ○원 · 메타 ○원"으로 교체 (네이버 키워드 수요만큼 채우고 남는 돈을 메타, `optimize_allocation` 재사용). 비율별(네이버 100/70/50/30/0%) 이익 비교 표
- Acceptance: 검색어 없거나 네이버 예측 실패 → 메타 대략값 + 등급 D 표시
- Test seams: `coach.split_budget()` 단위 테스트 (포화 지점 이전에는 네이버 우선, 예산 합 보존)
- Blocked by: 1.1

### Phase 2: 범위와 확률 (Q2) + 데이터 신뢰 등급
Verified when: 답 보기 첫 숫자가 "이익 범위 ○~○만 원, 이익 날 확률 ○%"이고, 모든 입력값 옆에 A~D 배지가 있다.

#### Step 2.1: 신뢰 등급 체계 (Size: S)
- Acceptance: 모든 엔진 입력에 등급 필드(A 실측 / B 플랫폼 예측 / C 공개 데이터 / D 가정). 화면 배지와 등급표 캡션
- Test seams: `defaults.py` 값마다 등급이 있는지 테스트
- Blocked by: none

#### Step 2.2: 몬테카를로 시뮬레이션 (Size: M)
- Acceptance: CPC·CVR·재구매 등 불확실 입력을 등급별 폭으로 N회 뽑아 12개월 이익 분포 → 범위(10~90%)와 이익 날 확률
- Acceptance: 같은 시드면 같은 결과, 1회 계산 1초 이내 (N=1,000 기준)
- Test seams: `src/engine/montecarlo.py` 테스트 (폭 0이면 기존 결정론 결과와 일치)
- Blocked by: 2.1

#### Step 2.3: 신호등을 "100번 중 ○번" 표현으로 교체 (Size: S)
- Acceptance: 대표 표현 = "이 조건으로 한 달 광고를 100번 해 보면 1년 동안 ○번은 남고 ○번은 손해" + 100칸 막대 + "보통 ○만 ~ ○만 원"(10~90% 구간)
- Acceptance: 결론은 색이 아니라 행동 문장: 80번 이상 "해 볼 만해요" / 50~79번 "작게 시험해 보세요" / 50번 미만 "지금은 광고보다 준비가 먼저". 색은 보조
- Acceptance: 대비 한 줄 "첫 구매만 보면 100번 중 ○번" (ROAS vs LTV). "필요 구매 비율"은 "왜 이렇게 나왔나요?" 접기 안의 근거로 유지
- Acceptance: 시험 예산 기본 선택 규칙은 결론 문장에 맞춤 (50번 미만이면 "광고 안 함" 기본, v0.9.2 규칙 대체)
- Blocked by: 2.2

### Phase 3: 손익분기 재구매율 지도 (Q3) (Size: S)
Verified when: 답 보기에 객단가(가로) × 1년 재구매 횟수(세로) 지도, 내 위치 표시, 본전 선.
- Test seams: `coach.breakeven_grid()` (경계선이 손익분기식과 일치)
- Blocked by: 1.1

### Phase 4: 한 달 뒤 재계산 (Q4)
Verified when: 네이버·메타 리포트 CSV와 주문 수를 넣으면 컬럼 진단 문장, 과대 집계율, 예측 오차율, 다음 달 배분이 나온다.

#### Step 4.1: 계획 저장·불러오기 (Size: S)
- Acceptance: 단계 3에서 "내 계획 파일 받기"(JSON: 입력·예측·시작일), 단계 4에서 올리면 복원
- Blocked by: none

#### Step 4.2: 리포트 CSV 매핑 (Size: M)
- Acceptance: 네이버 검색광고 리포트·메타 광고 관리자 내보내기의 열 이름을 공통 지표(노출·클릭·비용·전환·전환매출, 메타는 도달·빈도·목적)로 자동 매핑, 틀리면 사용자 수정
- Test seams: 실제 내보내기 샘플(게이트 G5) 또는 공식 열 이름으로 만든 픽스처
- Blocked by: 4.1

#### Step 4.3: 진단 규칙 + 과대 집계율 + 예측 오차율 (Size: M)
- Acceptance: 규칙표(예: CTR 높고 구매 적음 → 상세페이지, 빈도 높고 CTR 하락 → 소재 피로, 메타 목적이 인지도인데 구매 기대 → 목적 안내)
- Acceptance: 과대 집계율 = (네이버 + 메타 리포트 전환 − 실제 주문) ÷ 실제 주문, 예측 오차율 = |예측 − 실측| ÷ 실측 (4.1 저장값 사용)
- Acceptance: 실측으로 다시 계산한 다음 달 배분
- Blocked by: 4.2

## Assumptions (틀리면 승인 전에 고쳐 주세요)
- A1. 리포트 열 이름: 네이버 검색광고·메타 광고 관리자 **공식 문서의 내보내기 열 이름**으로 매핑을 만들고, 팀원이 실제 내보내기 파일을 주면 그걸로 테스트를 바꿈.
- A2. 몬테카를로 불확실성 폭(초안): 등급 A ±10%, B ±25%, C ±40%, D ±60% (로그정규, N=1,000, 시드 고정). 가상 데이터로 민감도 확인 후 조정.
- A3. 챗봇: 모델은 비용이 낮은 Claude Haiku 계열, 대화 결과는 정해진 필드(상품·판매가·마진·예산·목적·검색어)만 받고 사용자가 확인한 뒤 반영. 키는 사용자가 `.env`·Streamlit Secrets에 넣음. 키·개인정보는 LLM에 보내지 않음.
- A4. 계획 저장은 로그인 없이 JSON 파일 내려받기·올리기.
- A5. 실행은 프로토타입 개발 세션, 각 Phase 끝마다 기획 세션이 테스트·배포 앱을 확인하고 UX 점검표 결과를 받음. 메인 앱 배포는 Phase마다.
- A6. 중간 발표(11/9)용 고정본이 필요하면 지금 main을 `release/v0.9` 앱으로 먼저 고정 (요청 시).
