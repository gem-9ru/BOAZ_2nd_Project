## 0. 왜 다시 짜나

팀 작업(11/6 회의, 메타 트래픽 칸 정리, 가상 광고 데이터 EDA)으로 제품의 중심이 **"얼마 써도 되나(손익)"에서 "어떻게 세팅하고 무엇을 고칠까"**로 옮겨 갔다. 팀원들이 제품의 내용(물어볼 칸, 받을 컬럼, 진단 규칙)을 이미 정해 왔으므로, 개발은 이것을 **데이터로 된 사양**으로 굳히고 그 사양을 읽어 도는 얇은 엔진과 화면을 만든다.

### 설계를 바꾸는 사실
1. 스마트스토어에는 메타 픽셀을 달 수 없음 → 판매는 스토어 NT 유입 주문으로만 판단. 트래픽 단계의 과대 집계는 "메타 랜딩 조회 vs 스토어 메타 유입" 비교(유입 집계 차이)
2. 3~4일치 클릭 단가로 경로를 고르면 틀림 → 짧은 데이터는 세팅 확인용, 경로 비교는 2주 이상
3. 인지도 효과는 마지막 클릭 통계에 숨고, 전후 비교는 시즌에 부풀려짐 → 시즌 보정 필수
4. 경로 우열은 "광고 본 사람의 브랜드 검색 비율"에 달려 있음 → 재지 못한 값은 범위로만

### PM 결정

|---|---|

| 2 | 첫 달 기본값은 메타 트래픽 + 네이버 검색. "알리기도 원해요"면 인지도 → 트래픽 조합(C1)을 **가설로** 제안 |

| 5 | LLM은 문구 초안과 자유 답변 해석에만. 숫자·판정은 규칙 엔진 |

## 1. 구조

### 사양 3개 (`specs/`)
| 파일 | 내용 | 원본 |
|---|---|---|
| `meta_fields.yaml`, `naver_fields.yaml` | 광고 관리자 칸마다 id, 단계, 종류(question / default / auto / precheck / llm / next_cycle), 질문 문구, 기본값, 설명, 연결된 규칙 | 희수 칸 정리표 3-1~3-4 |
| `columns.yaml` | 화면 이름 → 영문 열 이름 → 검사(필수, 단위, 비율 열은 합산 안 함) | 다정 엑셀 '컬럼 사전'·'실제_템플릿' |
| `rules.yaml` | 조건, 문장, 근거 숫자, 다음 달 바꿀 칸(`next_cycle.field`), 등급(가설/확인) | 다정 규칙 8개 + 희수 깔때기 규칙 |

예시:
```yaml
# meta_fields.yaml
- id: meta.adset.end_date
  stage: adset
  kind: question
  ask: "광고를 얼마 동안 하실 건가요?"
  default: "+14d"
  why: "비워 두면 끄기 전까지 계속 돈이 나가요"

# rules.yaml
- id: rule.placement_quality
  when: "an_click_share > 0.20"
  says: "클릭의 {an_click_share:.0%}가 다른 앱 광고 자리에서 나왔어요. 싸지만 잘 안 팔려요"
  next_cycle: {field: meta.adset.placements, set: {exclude: [audience_network]}}
  grade: hypothesis
```

**루프를 닫는 고리:** 규칙의 `next_cycle.field`가 칸 사양의 id를 가리킨다. 다음 달 세팅 = 이번 달 세팅 + 진단이 만든 변경 목록.

### 엔진 모듈
| 모듈 | 입력 → 출력 |
|---|---|
| `ingest` | CSV·엑셀 → 컬럼 사전으로 검사된 표 (메타 일별·노출 위치, 네이버 일별, 스토어 일별, 설문) |
| `metrics` | 표 → 빈도, 링크 CTR, AN·인스타 비중, 예산 사용률, 포화도, 마지막 클릭 CAC |
| `diagnose` | 지표 + 규칙 사양 → 진단 카드(근거 숫자) + 바뀔 칸 목록 |
| `effect` | 브랜드·카테고리 검색 + 설문 → 시즌 보정한 효과, "광고 덕분 주문" 범위 |
| `market` | 상품 단어 → 검색어 목적 묶음, 성별·연령·월별(쇼핑인사이트), 네이버 수요 |
| `planner` | 예산·수요 → 네이버 상한, 메타 몫, 도달·빈도, 기간 |
| `intake` | 칸 사양 → 챗봇 질문 → 세팅값 시트 |
| `tracking` | 세팅 → NT·UTM 링크 (고정 이름 규칙) |
| `plan_io` | 계획 파일 저장·불러오기 (세팅 + 가정 + 등급) |

### 기존 코드에서 가져올 것 (이것만)
`src/engine/keys.py`, `naver_source.py`의 키워드 도구·캐시, `naver_hub.py`(+ 쇼핑인사이트 경로 `/shopping/v1/category/keyword/{gender,age,device}`, `/shopping/v1/category/{gender,age}`, 11/15 호출 확인), `uploads.guess_columns`, 링크·쿠폰 생성기, `data/rag` 세팅 카드. 나머지는 `v1.1` 태그로 남기고 새 코드에서 쓰지 않음.

| 다정·희수 | 만원 실험 결과 (`실제_템플릿` 형식) | 실험 끝나는 대로 (시작 11/20 이전) |

## 5. 리스크
| 리스크 | 대응 |
|---|---|
| 규칙 기준값이 검증 전 가설 | 화면과 발표에 `가설` 등급. 만원 실험 값으로 하나라도 보정 |
| 브랜드 검색 비율 미측정 | C1 추천은 범위와 "이 값에 따라 달라져요"로만 |
| 가상 데이터와 규칙이 같은 가정에서 나옴 | 골든 테스트는 코드 검증일 뿐이라고 발표에서 구분 |
| 실제 데이터가 늦게 옴 | S1~S2는 가상 데이터로 끝내고, 실제 데이터는 파일 교체만으로 들어가게 |
| 다시 짜다 시간 부족 | 11/21 S1 점검에서 전환 결정 |
| 데이터랩 이용약관(캐시 기간·출처 표기) 미확인 | 화면에 출처 표기, 약관 확인 전까지 캐시는 로컬만 |
