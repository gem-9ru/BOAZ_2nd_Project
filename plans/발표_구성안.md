## 1. 레퍼런스에서 가져올 것 (지난 기수 2차 프로젝트 4개)

| 팀 | 주제 | 가져올 것 | 피할 것 |
|---|---|---|---|
| 시각화 1조 | 합성 로그 기반 추천 시스템 | 가상 데이터를 정석대로: 페르소나 설계 → 생성 규칙 → 생성 품질 검증(기준값 명시) → 유의하지 않은 결과도 그대로 보고 → "합성 데이터의 한계"를 결론으로. 대시보드 화면마다 "이 숫자가 낮아지면 → 이렇게" | 파이프라인 기술 설명이 길어짐 |
| 3조 CounsHelper | 상담사 보고서 자동화 | 기능마다 작업 흐름 한 장(입력 → 처리 → 출력), 데이터 구성 한 장(출처·건수·쓰임), 화면별 설명, 출처를 보여 주는 챗봇, 기대효과를 숫자로, 수익모델 | 모델 성능 근거가 약함 |
| 4조 JobSignal | 채용·기업 분석 대시보드 | "왜 이 데이터 출처인가", 수집 규모와 날짜, 결측 처리 이유, 점수 산식을 단계별로, 한계를 구체적으로 | 글이 너무 많음 |
| 시각화 2조 Drugon | 약물 오남용 대화형 대시보드 | 트랙 선택을 첫머리에, 챗봇 답변 분기(데이터에 있음 → 근거 답변 / 관련은 있음 → LLM / 무관 → 거절), 배포 링크, "기존 방식 vs 우리" 비교표 | 만들지 않은 기능을 기대효과로 말함 |

**공통 뼈대:** 문제(통계 근거) → 타겟·서비스 → 데이터 → 방법·구조 → 기능별 분석 → 화면별 설명 → 시연 → 결론·한계 → Q&A

**우리가 앞설 수 있는 지점**
- 레퍼런스는 모두 "만들었다"에서 끝남. 우리는 **세팅 → 결과 → 다음 세팅 루프**를 화면으로 보여 줌
- **매체 숫자를 그대로 믿으면 틀린다는 검증**: 3~4일 CPC로 고르면 틀림, 시즌 때문에 전후 비교가 부풀려짐 (+31% → 보정 +1%)
- 1조처럼 가상 데이터의 한계를 정직하게 말하되, **만원 실험이라는 실제 숫자**를 더함
