## 1. 개요

| 항목 | 내용 |
|---|---|
| 제품 | 광고 코치 v2 (Prototype Ver 2.0.0) |
| 사용자 | 온라인 광고를 처음 하는 1인 셀러 (예시: 소연베이크, 수제 구움과자, 스마트스토어, 월 30만 원) |
| 하는 일 | ① 세팅: 챗봇 질답으로 네이버 검색광고·메타 광고 관리자 칸을 채운 '세팅값 시트'를 만든다 → ② 실행: 켜기 전 준비 체크리스트와 결과 올릴 날 → ③ 진단: 한 달 결과로 진단 카드·효과 확인·다음 달 바뀐 칸 |
| 핵심 숫자 | 광고 관리자 칸 62개(메타 47 + 네이버 15) 중 사장님께 묻는 질문 13개 (홈 화면 문구, `home.counts()`) |
| 설계 원칙 | 숫자·판정은 규칙 엔진, LLM은 광고 문구 초안과 도움말 보충에만. 키가 없어도 저장된 예시 데이터와 문장 틀로 끝까지 동작 |

## 2. 구조와 실행

```
v2/
  app/      화면 (Streamlit 1.50): main, home, setup, run, diagnose, chat, board, guide, state, ui, data, viz[작업 중]
  engine/   순수 파이썬 엔진: conversation, chat_parse, helpdesk, market, naver_api, planner, intake,
            tracking, copywriter, plan_io, diagnose, metrics, effect, ingest, datacheck, specs
  specs/    사양 YAML: meta_fields, naver_fields, columns, rules, assumptions, help/{meta,naver}
  data/     demo/소연베이크_가상광고데이터.xlsx, cache_examples/(시연용 네이버 응답 12개), cache/(git 제외)
  tests/    pytest 9개 파일 + fixtures/help_eval_{meta,naver}.yaml
```

- 실행: `streamlit run v2/app/main.py` (프로젝트 루트). 로컬 Python 3.9(`.venv`), 배포는 Python 3.12 (`plans/개발_티켓.md` T15).
- 3.9 호환 필수: `match`, `X | Y`, `list[int]` 문법 금지 (`DEV_CONTRACT.md` 0장).
- 쪽 나누기: `st.navigation` — 홈(`/`), ① 세팅(`/setup`), ② 실행(`/run`), ③ 진단(`/diagnose`). 배포 앱은 `~/+/<경로>`로 열면 iframe 없이 열린다.
- 의존성(`requirements.txt`): streamlit 1.50.0, plotly 7.1.0, pandas 2.3.3, numpy 2.0.2, scipy 1.13.1, requests 2.32.5, openpyxl 3.1.5, xlrd 2.0.1, anthropic 0.125.0, pyyaml 6.0.2, pytest 8.4.2.

### 화면 사이 상태 (`v2/app/state.py`)
모두 `st.session_state`. 기본값은 `state._defaults()`.

| 키 | 내용 |
|---|---|
| `store` | 가게 정보 (name, product, product_slug, store_type, price, margin_per_order, budget, month, seeds, …) |
| `media` | `["meta", "naver"]` (기본값, 화면에서 바꾸는 입력은 없음) |
| `answers` | 칸 id → 답 |
| `budget_plan` | `planner.BudgetPlan`을 dict로 |
| `market` | `market.MarketReport` 원본 (그래프용) |
| `chat` / `chat_pending` / `chat_problem` | ① 세팅 대화 상태(JSON dict) / 처리 대기 입력 / 오류 문장 |
| `setup_step`, `month_index`, `history`, `created` | 진행 단계, N개월 차, 진단 기록, 생성일 |
| `is_demo`, `ad_start`, `run_checks`, `sheet_checked`, `diag_done` | 예시 여부, 광고 시작일, 체크리스트, 시트 '옮겨 적음', 진단 완료 |
| `rd_run`, `rd_diag` | ② ③ 안내 대화 상태 (`board.py`) |
| `guide_focus`, `guide_pref`, `w_guide` | 캐릭터가 가리킬 대상, 캐릭터 보이기 설정 |

`state.setup_done()` = `setup_step >= LAST_STEP` 그리고 `budget_plan`이 있음. ②·③ 화면의 잠금 조건이다.

## 4. 대화 엔진 상태 흐름 (`v2/engine/conversation.py`)

- 순수 파이썬, LLM 없음. 상태는 JSON으로 저장 가능한 dict. 공개 함수는 모두 **새 state를 돌려주고** 받은 state는 고치지 않는다(`copy.deepcopy`).
- 진입점: `start(media, month)`, `handle(state, text, sv)`, `choose(state, chip, sv)`, `edit(state, key)`, `skip_rest(state, sv)`, `to_answers`, `to_store`, `demo_state(sv)`, `progress`, `editable`, `turns`, `last_turn`, `take_stream`, `set_help_text`, `make_services(online)`.
- `Services`(화면이 넣음, 테스트는 가짜): `market(seeds)`, `plan(store, market, objective, days)`, `help(question, step_id, ctx)`, `questions(media)`, `copies(product, strengths)`, 선택 `is_question(text)`, `market_error()`.
- `Turn`: role(user/bot), text, kind(text·confirm_card·market_card·budget_card·help·error·done), data, chips.

### 4.1 단계

`STAGES = ["가게", "확인", "손님", "예산", "세팅 질문"]`, phase → 단계 번호: store 0 · confirm 1 · market 2 · budget 3 · ask 4 · done 5.

```
store ──(7개 답)──▶ confirm ──맞아요──▶ market ──이대로 쓸게요/자료 없이──▶ budget ──이대로 할게요──▶ ask ──(질문 끝)──▶ done
  ▲                   │고칠래요                │다른 단어로(seeds)          │목표·기간 다시
  └── fix(항목 고르기) ┘                       └ fail ─ 다시 찾아볼게요/자료 없이 넘어갈래요
```

|---|---|---|---|---|

### 4.2 질문 판별과 도움말 끼어들기
- 모든 단계에서 글이 질문이면(`sv.is_question` = `helpdesk.is_question`, 실패 시 `chat_parse.looks_like_question`) `sv.help(글, 지금 칸 id, ctx)` 답을 help Turn으로 보이고 **같은 질문을 다시** 묻는다.
- 이름·상품·영문 이름·검색 단어처럼 자유 글 칸은 `looks_like_question(strict=True)`도 참일 때만 질문으로 본다(상품명이 질문으로 오인되지 않게).
- 칩은 질문으로 보지 않는다.
- 지금 칸 id: ask→그 칸, market→`naver.keywords.list`(네이버를 쓸 때), budget→objective/end_date 칸(메타를 쓸 때).
- llm 스트림은 JSON에 못 넣으므로 모듈 변수 `_STREAMS[turn_id]`에 두고 `take_stream`으로 한 번만 꺼낸다.

### 4.3 기타
- `skip_rest`: ask·done 단계에서만. 남은 칸은 `default`(없으면 ""), 문구 칸은 장점 없이 생성한 첫 문구.
- `editable`: 가게 7개(영문 이름까지 답했을 때) → 내 손님(검색 단어) → 예산 나누기 → 답한 칸(목표·기간 제외).
- `demo_state`: 소연베이크·수제 구움과자·26,000원·8,000원·30만원·스마트스토어·soyeonbake를 차례로 넣어 확인 카드까지.

## 5. 도움말 엔진 (`v2/engine/helpdesk.py`)

`answer(question, step_id=None, ctx=None, client=None) -> HelpAnswer(kind, text, field_id, sources, stream)`

찾는 순서:
1. **코치 숫자** (`_COACH_RULES` 정규식 7종: split 나누기 · daily 하루 예산 · breakeven 본전 · clicks · reach · orders · bid) → `kind="coach"`. ctx의 예산 계획·가게 값만 쓰고, 없으면 "아직 계산된 숫자가 없어요…". orders는 예산 판과 같은 `planner.expected_orders`로 "약 N~M건, 근거 D"(11/16 고침, 12장 D6).
2. **미리 쓴 도움말** (`specs/help/*.yaml`): 질문 단어(조사 떼기·동의어)와 칸의 라벨·키워드·faq·요약 겹침 점수. 지금 칸 ×1.12, 같은 단계 ×1.05, 다른 매체는 보지 않음. `MATCH_MIN 0.25` 이상이고 근거 낱말이 충분하며 (지금 칸이거나 `HIGH_MIN 0.5` 이상)이면 `kind="help"`. faq와 0.6 이상 겹치면 faq 답, 아니면 summary. 다른 칸이면 "(‘라벨’ 칸 설명이에요)" 머리말.
3. **LLM** (client가 있고 광고 관련 질문일 때만, 7.3) → `kind="llm"` 스트림.
4. 애매하지만 LLM이 없거나 실패 → 가장 가까운 칸의 미리 쓴 답.
5. 광고와 무관 → `kind="none"` "광고 세팅과 관련된 질문에 답할 수 있어요…". 그 밖 → "이 질문은 제가 가진 자료에 없어요…" + 지금 칸의 출처 링크.

`is_question(text)`: "2만 6천원", "네", "1", "스토어 방문 늘리기", "휘낭시에, 쿠키" 같은 답은 False (계약 5장).

### 7.3 저장본(캐시) 순서 — `fetch_cached`
1. `v2/data/cache/` (내가 받은 응답, 7일 안이면 사용; 오프라인이면 기간 상관없이)
2. `v2/data/cache_examples/` (시연용 고정: 디저트 예시 seeds `휘낭시에, 쿠키선물세트, 답례품쿠키, 디저트선물, 수제쿠키`, keywordstool 1개 + hub 11개)
3. 온라인 호출 → 성공하면 `cache/`에 응답만 저장(키·헤더 저장 안 함)
4. 호출 실패 시 오래된 `cache/` 저장본(이때도 `last_error`는 남김)
5. 모두 없으면 None
- 저장본 이름: `{kind}_{md5(key)[:10]}.json`. HUB 키는 (경로, 분야, 키워드, 단위)로만 만들어 기간과 상관없이 시연 저장본이 맞는다.
- 화면 대화의 `market` 서비스는 **저장본(online=False) 먼저**, 없을 때만 온라인 (`conversation.make_services`).
- `naver_api.last_error()`: 마지막 실패 이유(쉬운 문장). 조회 시작 때 지워짐. 모든 예외를 잡아 앱을 멈추지 않는다(`_guarded`).
- `naver_api.reset_fetched()` / `oldest_fetched()`: 한 조회 묶음에서 쓴 응답(저장본·예시 저장본·실시간)의 받은 날을 모아 가장 오래된 날을 돌려줌 → 화면 조회일 표시(11/16 추가).

- 클라이언트 생성: 화면 대화가 쓰는 클라이언트는 `conversation._client()` → **`copywriter.make_client()`** 하나를 도움말과 문구가 같이 쓴다 (`max_retries=1`, `timeout=30`; 도움말 호출은 요청마다 `timeout=15`를 다시 줌). `helpdesk.make_client()`(`max_retries=0`, `timeout=15`)는 따로 있으나 화면 대화 경로에서는 쓰지 않는다.
- 키 읽기: `helpdesk.read_api_key()`는 secrets → 환경 변수 → `.env`를 직접 읽는다. `copywriter._read_key()`는 v2 `naver_api.read_keys`로 같은 순서로 읽는다(11/16 고침, 12장 D5).
- 예시 계획(`state.load_demo_plan`)과 `state.make_copies(live=False)`는 `client=False`로 항상 문장 틀 → 키가 있어도 같은 결과.
- 배포 앱에는 `ANTHROPIC_API_KEY`와 네이버 키(검색광고·HUB)가 Streamlit secrets로 설정돼 있다 (개발 담당 확인, 2026-11-16). 키 값은 문서에 적지 않는다. 배포 화면에서 저장본에 없는 단어의 실시간 검색(키워드 도구 + 데이터랩)과 AI 답(LLM 경로)이 동작함을 확인했다(12.3 N1).

## 9. 계획 파일 형식 (`plan_io.py`)

```json
{"format": "ad-coach-plan", "version": "2.0.0", "month_index": 1, "created": "YYYY-MM-DD",
 "store": {...}, "media": ["meta","naver"], "answers": {...}, "budget_plan": {...},
 "history": [{"month": 1, "fired": ["rule.…"], "changes": [{"field_id","label","before","after","note"}]}]}
```
- `from_json` 거절 조건 (모두 `PlanError`, 끝에 "앞에서 내려받은 '계획 파일'을 올렸는지 확인해 주세요."): 글자로 못 읽음, 빈 파일, JSON 아님, 다른 format, 필수 항목(store·media·answers·budget_plan·history) 없음, version이 `2.`로 시작하지 않음, 항목 타입 다름, month_index가 1 이상 정수가 아님. UTF-8 BOM 허용.
- `next_month(plan, findings)`: 칸마다 fired 규칙 제안 중 **지금 값과 다르고 지난 기록에 나온 적 없는** 첫 값(rules.yaml 순서)을 고름 → `intake.apply_changes` → 하루 예산 칸이 바뀌면 `budget_plan`의 `meta_daily`/`naver_daily`도 맞춤 → month_index+1, history에 이번 달 기록 추가. 예산·결과당 비용 같은 측정값과 제외 키워드는 '나온 적 있는 값' 예외.

| L3 | 브랜드 검색 비율 미측정 → C1 추천은 범위로만 | 측정하려면 실제 광고가 필요 | 만원 실험에서 설문(`survey` 표, "어디서 알게 됐나요")과 스토어 브랜드 검색을 같이 모아 값 하나라도 잼. 그 전에는 지금처럼 범위 + "이 값에 따라 달라져요" 유지 |
| L4 | 가상 데이터 점검 3줄이 범위 밖 (C3 CPM 2,602원 · C1 네이버 CTR 1.41% · C4 지출 +24.6%) | 앱 결함이 아니라 가정과 가상 데이터가 어긋난 사실 | 점검표가 제 역할을 한 증거로 발표에 그대로 씀. 다정과 함께 "가정을 넓힐지(근거 필요) / 데이터를 다시 만들지" 결정 |
| L5 | 네이버 칸 사양이 개발 초안, 네이버 도움말 15항목 중 14개가 △(대행사 블로그 출처) | 배포 앱 답변에도 "공식 아님 · 대행사" 출처가 그대로 보임(직접 확인) | ① 네이버 검색광고 고객센터·검색광고 교육(공식) 페이지를 다시 조사해 출처를 바꾸고 ✅로. 이전 작성 때 "이 환경에서 열어 보지 못함"이었던 공식 홈은 내장 브라우저로 열 수 있음. ② 희수·제명 리뷰를 YAML 체크리스트로(칸마다 '공식 화면 이름과 같음' 체크) |
